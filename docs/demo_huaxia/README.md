# 华夏基金智能客服 · 开箱即用功能演示套件

> 用途：在 RAGFlow 上预置一套「华夏基金基金客服」场景的演示数据，
> 让售前同学可以直接拿去给客户（华夏基金金融科技部）做产品演示。
> 覆盖华夏基金需求清单里判定为 **开箱即用 / 纯配置** 的 5 项：
> 寒暄知识库、基金 FAQ 知识、用户咨询日志、模拟测试（检索测试）、系统日志。
> （批量测试的「评估」API 本版正在从 Python 迁 Go、路由未注册，演示改用稳定的「检索测试」页面 + 本套测试集替代，详见 `演示脚本.md`。）

## ⚠️ 重要：Q&A（qa）解析器的文件格式要求

演示/交付数据必须符合 `qa` 解析器的切分规则，否则文档会显示「已解析」但**分块数为 0**
（解析步骤成功 ≠ 分块有内容，这是最容易踩的坑）。

**唯一可靠格式：问题与答案同行，用真实 TAB 分隔**（半角逗号也可，但答案里含逗号时易出错，优先用 TAB）：

```
基金怎么买<TAB>您可通过以下渠道购买华夏基金产品……
赎回基金多久到账<TAB>到账时间取决于基金类型……
```

打开文件时应能看到列对齐；用记事本「显示 → 显示 Tab」确认中间是 `→` 箭头即正确。
**不要**写成下面这些形式（实测均产生 0 分块）：

| ❌ 错误写法 | 为什么失败 |
|---|---|
| `Q: 你好` 换行 `A: 您好…` | 分行写法，切不出 2 段 |
| `# 你好` 换行 `您好…`（md 标题式） | 同上，切不出 2 段 |

**原理**（源码依据，便于向客户/同事解释）：
- `internal/ingestion/component/parser_dispatch.go:322` `buildParserOutputs` 把所有文件类型的
  `output_format` **硬编码为 `"json"`**，下游 chunker 拿到的永远是 JSON。
- 因此 `qa.go` 的 `extractQAText` → `detectDelimiter` 生效，它**只认「按 TAB 或逗号切成恰好 2 段」的行**。
- `qa.go` 里的 `extractQAMarkdown`（md 标题提取）在当前流水线里**不会被调用**，写了也无效。

> 本套演示数据已按上述格式生成并自检通过（寒暄库 12 块、FAQ库 8 块）。
> 导入后请到知识库「文档」页确认 **分块数 > 0**，再点开任一分块看到 `问题：… 回答：…` 即为正常。

## 两种灌数据方式（二选一）

### 方式 A：Web 界面手动导入（最稳，推荐给不熟命令行的人）
1. 启动 RAGFlow，登录后进入「知识库」。
2. 新建知识库「华夏基金-寒暄库」，解析方式选 **Q&A（qa）**，把 `华夏基金-寒暄知识库.txt` 拖进去。
3. 新建知识库「华夏基金-基金FAQ库」，解析方式同样选 **Q&A（qa）**，把 `华夏基金-基金FAQ知识库.txt` 拖进去。
4. 进入「聊天」→ 新建助手，绑定上面两个知识库，起名「华夏基金智能客服-小夏」。
5. 在助手里手动聊几条（或按 `测试集.md` 问几个问题），咨询日志自动产生。

### 方式 B：脚本一键灌入（适合反复重置演示环境）
```bash
pip install requests
# 先确认你的 RAGFlow 地址和 API Key（右上角头像 → API）
python seed_demo_data.py \
    --base-url http://localhost \
    --api-key <你的API_KEY> \
    --embedding-model BAAI/bge-large-zh-v1.5 \
    --llm-id <你已配置的模型ID，如 glm-4 / qwen-max>
```
脚本会：建 2 个知识库 → 上传 2 个 txt（qa 解析）→ 建 1 个对话助手 → 自动发 6 条消息生成咨询日志，
并把建好的 ID 写入 `demo_state.json`，方便后续清理。

## 环境前置
- RAGFlow 已部署（Go 服务 + 依赖：MySQL/PG、Kvrocks、NATS、MinIO、Infinity/ES、embedding 模型）。
- 已在「模型提供商」里配好至少 1 个可用的 LLM 和 1 个 embedding 模型。
- 演示前确认两个知识库的文档状态为「已解析（绿色）」，且**分块数不为 0**（寒暄库 12、FAQ库 8）。

## 演示顺序建议
