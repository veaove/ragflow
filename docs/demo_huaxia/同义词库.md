## 一、为什么是这 14 组

词库不是「把想到的词都塞进去」，而是**每个标准词都必须真实出现在 FAQ 知识点文本里**。
原因是检索增强的链路是「用户问法 → 命中别名 → 扩展成标准词 → 用标准词去召回分块」；
如果标准词本身不在分块里，扩展回去照样召不回，等于白配。

初版曾把「APP / 官网 / 银行 / 卖出 / 买入 / 费用 / 华夏」这类泛词收进词库，
但「APP」出现在 8 条答案里的 4 条，一旦归一会把所有查询都往这个词上拽，污染全库——已全部剔除。

## 五、验证结论

| 校验项 | 结果 | 含义 |
|---|---|---|
| 标准词锚定 | **14/14** | 每组标准词都能在其对应知识点的标准问/答案里找到 |
| 口语化问法覆盖 | **25/25** | 测试集里 25 条口语化问法全部能触发期望的词组 |

覆盖验证用的是逐字包含匹配（问法里出现组内任一别名即算触发），实际检索还有分词、
向量相似度、阈值过滤，最终以「检索测试」页实际命中为准。

## 六、词库和相似问的分工（别互相替代）

| | 词汇别名表 | chunk 相似问 |
|---|---|---|
| 管什么 | **术语归一**：把同一概念的不同叫法收敛成检索词 | **整句改写**：把客户的口语问法对齐到标准问 |
| 粒度 | 词/短语 | 完整问句 |
| 作用位置 | 查询扩展阶段，改检索词 | 召回阶段，改匹配对象 |
| 维护成本 | 一组词一次维护，全库受益 | 每个知识点单独挂 |

典型例子：「手续费」「费率」→「申购费」是**术语**，进词库；
「刚发的工资想理财，在哪能买基金」是**整句**，只能挂在「基金怎么买」这个分块的相似问上。

只有词库没有相似问，遇到完全不含术语的口语问法仍会漏召；反过来只挂相似问、不配词库，
客户换个说法就失效。**两者要配套用。**

## 七、后续维护建议

1. **按产品线扩**：现在只有基金品类，接债券/保险/理财后，在 `fund` 之外新增领域，
   别把不同品类的术语混在一组里。
2. **盯命中率**：演示时用「检索测试」逐条跑测试集，漏召的问法现场补成相似问，
   反复出现的再抽象成词组——**从真实日志长出来的词库才准**。
3. **华夏专属词单独管**：产品全称、客服话术、系统名称这类强品牌绑定词放 `hx`，
   换客户时整组停用即可，不影响通用词。
4. **别加泛词**：像「APP」「官网」「账户」这类高频但无区分度的词，加进去会污染所有查询。
