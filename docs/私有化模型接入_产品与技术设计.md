# 第一部分：产品设计

## 1.1 问题定义

当前模型配置页左侧「可选模型」是一份**预置厂商清单**（约 40 家），用户只能从中选择并填写 API Key 与 Base URL。想接入公司内网自建的推理服务（vLLM / Ollama / Xinference / 自研网关）时，找不到入口。

**关键澄清**：这**不是"不支持私有化"**。技术侧已内置 `vllm`、`ollama`、`xinference`、`localai`、`lm-studio`、`openai-api-compatible` 六个本地推理驱动，且 URL 校验有专门的宽松版本允许内网与回环地址。

**真正缺的是两件事**：
1. 产品层：没有「新建自定义模型服务」的入口，用户无法把自己的服务加进清单
2. 结构层：厂商名既当"显示名"又当"驱动标识"，用户起的名字一旦不是预置英文名，调用会失败

---

## 1.2 用户与场景

| 角色 | 场景 | 频次 | 诉求 |
|---|---|---|---|
| 企业 IT / 算法工程师 | 公司内网部署了 vLLM 集群，要把 Qwen 接进平台 | 一次性 + 变更时 | 填地址就能用，不想改配置文件 |
| 租户管理员 | 采购了第三方私有化推理服务，有独立网关和密钥 | 一次性 | 能起中文名区分（"财务专用模型"） |
| 交付/实施人员 | 客户现场部署，模型服务地址因客户而异 | 每项目一次 | 不改镜像、不改代码就能配 |

**共性诉求**：把「一个可访问的模型服务地址」变成「平台里可选可用的模型」，且**名称由用户自己定**。

---

## 1.3 方案对比

| 方案 | 做法 | 用户体验 | 实现成本 | 风险 | 结论 |
|---|---|---|---|---|---|
| **A 自定义模型服务（推荐）** | 左侧列表加「+ 添加自定义模型服务」，用户填显示名 + 选协议模板 + Base URL + API Key | 好：任意命名、任意地址 | 中 | 中（SSRF） | **推荐** |
| B 只放开 Base URL | 仍从预置厂商里选（如 Xinference），只允许改 Base URL | 差：名字改不了，多个内网服务无法区分 | 低 | 低 | 备选（快速上线版） |
| C 改配置文件 | 交付人员改 `conf/models/*.json` 并重启 | 差：需运维介入，无法自助 | 低 | 低 | 不采用（违背自助目标） |

**选 A 的理由**：租户级自助是核心价值。B 方案在"一个客户有多套模型服务"时立刻失效（都叫 Xinference，无法区分）。

**但采纳 B 的一个设计点**：A 的实现不新建协议，而是**复用现有预置厂商的协议模板**，所以 A 是"B 的超集"。

### 交互规则

| # | 规则 | 理由 |
|---|---|---|
| 1 | 「显示名称」与「协议类型」分开 | 名称可中文可任意；协议决定调用方式，不能由用户乱填 |
| 2 | 「测试连接」在保存前可点，失败不阻断保存 | 内网环境可能只有保存后由管理员放通，不能强制 |
| 3 | 模型清单支持"自动拉取"与"手动填写"两种 | 部分私有化网关不实现 `/v1/models`，必须能手填 |
| 4 | 保存后左侧列表出现该项，带「自定义」标签 | 与预置厂商视觉区分，且允许编辑/删除 |
| 5 | 删除自定义服务前二次确认，提示"已绑定的应用将无法调用该模型" | 防误删导致线上应用挂 |

## 1.5 功能需求

| 编号 | 需求 | 业务规则 | 验收标准 |
|---|---|---|---|
| FR-P01 | 自定义服务入口 | 左侧列表底部固定展示，与预置厂商用分隔线隔开 | Given 打开模型配置，Then 看到「+ 添加自定义模型服务」 |
| FR-P02 | 新建表单 | 显示名、协议类型、服务地址为必填；API Key 与超时选填 | Given 缺必填项，Then 保存按钮禁用并标红 |
| FR-P03 | 显示名唯一性 | 同一租户内显示名不可重复 | Given 重名，Then 提示「该名称已存在」 |
| FR-P04 | 协议类型 | 下拉仅提供已验证的六种协议；不提供"自定义协议" | Given 选择协议，Then 驱动按该协议分派 |
| FR-P05 | 地址校验 | 仅允许 http/https；保存时做语法校验；允许内网/回环 | Given 填 `ftp://`，Then 报错「不支持的协议」 |
| FR-P06 | 自动拉取模型 | 调用该协议对应的模型列表接口，成功则回填 | Given 服务可达，Then 列出可用模型 |
| FR-P07 | 手动填写模型 | 每行填模型名 + 类型（LLM / Embedding / Rerank / ASR / VLM / TTS） | Given 手填 2 个模型，Then 保存后可在模型选择里看到 |
| FR-P08 | 测试连接 | 校验地址可达 + 鉴权通过；返回耗时与错误原因 | Given 地址不通，Then 显示具体错误（超时/401/404） |
| FR-P09 | 编辑 | 可改显示名、地址、密钥、模型清单 | Given 改完保存，Then 已绑定的应用下次调用生效 |
| FR-P10 | 删除 | 二次确认；提示影响范围 | Given 确认删除，Then 该服务与其模型从列表消失 |
| FR-P11 | 默认模型可选 | 自定义服务的模型可被设为租户默认模型 | Given 设为默认，Then 新建对话使用该模型 |
| FR-P12 | 权限 | 仅租户管理员可增删改；普通成员只读 | Given 普通成员，Then 无编辑按钮 |

| 场景 | 表现 | 处理 |

# 第二部分：技术设计

## 2.1 现状盘点（基于当前代码）

| 层 | 位置 | 现状 |
|---|---|---|
| 厂商模板 | `conf/llm_factories.json`、`conf/models/{factory}.json` | 只读，随镜像发布，约 40 家 |
| 驱动分派 | `internal/entity/models/factory.go:33` `CreateModelDriver` | **硬编码 switch**，约 40 个 case |
| 已支持的私有化驱动 | 同上 | `vllm` / `ollama` / `xinference` / `localai` / `lm-studio` / `openai-api-compatible` |
| 租户厂商 | `entity/tenant_model_provider.go` | `provider_name` + `tenant_id`，唯一约束 `(tenant_id, provider_name)` |
| 租户实例 | `entity/tenant_model_instance.go` | `instance_name` + `provider_id` + `api_key` + `status` + `extra`(512 JSON) |
| 旧模型表 | `entity/tenant_llm.go` | `llm_factory` + `api_key` + `api_base` + `max_tokens` |
| URL 安全 | `internal/common/http.go:449` `AssertURLSchemeSafe` | **已允许内网与回环**，注释明确点名 Ollama / vLLM / Xinference |

**结论**：不需要新建协议栈，需要做的是「产品入口 + 名称与驱动解耦」。

---

## 2.2 核心矛盾：provider_name 兼作驱动标识

```go
// internal/entity/models/model.go:304
provider.ModelDriver, err = modelFactory.CreateModelDriver(provider.Name, provider.URL, provider.URLSuffix)
```

`provider.Name` 直接进 switch：

```go
switch providerName {  // internal/entity/models/factory.go:35
case "vllm":     return NewVllmModel(...)
case "ollama":   return NewOllamaModel(...)
...
}
```

用户如果起名「财务专用模型」，switch 匹配不到，调用直接失败。

**这是本次改造的技术核心**：必须把「显示名」与「驱动模板」拆成两个字段。

---

## 2.3 数据模型改造

### 方案：`tenant_model_provider` 增加两个字段

```go
type TenantModelProvider struct {
    ID           string `gorm:"column:id;primaryKey;size:32"`
    ProviderName string `gorm:"column:provider_name;size:128;not null;index:idx_tenant_provider_unique,unique"`
    TenantID     string `gorm:"column:tenant_id;size:32;not null;index;index:idx_tenant_provider_unique,unique"`
    // Driver 是协议模板名（vllm/ollama/xinference/localai/lm-studio/openai-api-compatible），
    // 决定用哪个 ModelDriver。为空表示"预置厂商"，回退到 ProviderName。
    Driver string `gorm:"column:driver;size:64;default:''"`
    // IsCustom 标记租户自建，前端据此显示「自定义」标签并开放编辑/删除。
    IsCustom bool `gorm:"column:is_custom;not null;default:false"`
    BaseModel
}
```

**为什么用 Driver 而不是复用 extra**：
- `extra` 在 instance 表上（一 provider 多实例），协议是 provider 级属性，放 provider 表语义更准
- 驱动分派时只需读 provider，不必反序列化 instance 的 JSON

**兼容性**：`driver` 默认为空 → 分派时回退 `provider_name`，存量数据零影响。

### instance 表承载连接参数

`tenant_model_instance.extra`（512 JSON）存：

```json
{
  "base_url": "http://10.0.1.20:8000/v1",
  "timeout_sec": 60,
  "headers": { "X-Org-Id": "abc" }
}
```

> 现有 `tenant_llm.api_base` 是旧路径，新逻辑读写 `extra.base_url`；迁移期两者并存，见 §2.7。

## 2.4 驱动分派改造

```go
// internal/entity/models/model.go
func resolveDriverName(p *Provider) string {
    if p.Driver != "" {
        return p.Driver
    }
    return p.Name  // 预置厂商：name 即 driver
}

provider.ModelDriver, err = modelFactory.CreateModelDriver(
    resolveDriverName(provider), provider.URL, provider.URLSuffix)
```

`CreateModelDriver` 本身不改，只改调用方传参。**改动面 1 处调用 + 1 个辅助函数**。

## 2.5 接口设计

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/v1/tenants/:tenant_id/model-providers` | 列表（预置 + 自定义，含 `is_custom`） |
| `POST` | `/api/v1/tenants/:tenant_id/model-providers` | 新建自定义服务 |
| `PUT` | `/api/v1/tenants/:tenant_id/model-providers/:id` | 编辑 |
| `DELETE` | `/api/v1/tenants/:tenant_id/model-providers/:id` | 删除（校验是否被应用引用） |
| `POST` | `/api/v1/tenants/:tenant_id/model-providers/test` | 连通性测试（不落库） |
| `POST` | `/api/v1/tenants/:tenant_id/model-providers/:id/fetch-models` | 拉取模型清单 |

### 请求示例（新建）

```json
POST /api/v1/tenants/t_xxx/model-providers
{
  "provider_name": "财务专用模型",
  "driver": "vllm",
  "base_url": "http://10.0.1.20:8000/v1",
  "api_key": "",
  "timeout_sec": 60,
  "models": [
    { "name": "qwen2.5-72b-instruct", "type": "LLM" },
    { "name": "bge-m3", "type": "EMBEDDING" }
  ]

```

### 服务层要点

- 创建时校验 `(tenant_id, provider_name)` 唯一
- `driver` 必须在白名单内（六个协议之一），**不接受任意值**
- 模型写入同步 `llm` 表（`fid` = provider 的实例标识），保证模型选择器能查到

## 2.6 安全设计（本次最关键）

### SSRF：这是"特性"也是"风险"

私有化部署必然访问内网，所以**不能一刀切禁内网**。分级处理：

| 目标地址 | 策略 | 理由 |
|---|---|---|
| 公网地址 | 允许 | 正常的云厂商 |
| 内网段（10/172.16-31/192.168） | **允许**（用 `AssertURLSchemeSafe`） | 私有化部署的常态 |
| 回环 127.0.0.1 | 允许 | 单机部署常见 |
| **云元数据 `169.254.169.254`** | **必须拉黑** | 可窃取云主机凭证，最高危 |
| `file://` / `gopher://` 等 | 拒绝 | 已有 `AllowedURLSchemes = [http, https]` |
| 重定向到上述禁止地址 | 禁止 | 需禁跟随跨域重定向 |

**落地**：新增 `AssertURLForModelProvider`，在 `AssertURLSchemeSafe` 基础上只加一条"拒绝 169.254.169.254 与 link-local 段"。

### 其他

| 项 | 要求 |
|---|---|
| 密钥存储 | `api_key` 落库前加密（现有 `api_key` 是明文列，新路径建议复用既有加密工具） |
| 密钥回显 | 前端只显示掩码，编辑时不回传原值则保留原密钥 |
| 超时 | 默认 60s，上限 300s，避免慢服务拖死连接池 |
| 响应体大小 | 拉取模型清单限制 1MB，防超大响应打爆内存 |
| 权限 | 仅租户 owner/admin 可写；接口侧校验，非仅前端隐藏 |

## 2.7 迁移方案

| 步骤 | 内容 | 回滚 |
|---|---|---|
| 1 | `tenant_model_provider` 加 `driver`(默认空)、`is_custom`(默认 false) | 直接 drop 列 |
| 2 | 存量数据 `driver` 保持空 → 分派回退 `provider_name`，行为不变 | 无需回滚 |
| 3 | 自定义服务的 `base_url` 写在 `instance.extra`；`tenant_llm.api_base` 暂不动 | 旧路径仍可读 |
| 4 | 后续版本统一到 `extra`，再废弃 `tenant_llm.api_base` | 分阶段 |

**本期不改 `tenant_llm`**，避免影响既有模型调用链。

## 2.8 测试要点

| # | 用例 | 断言 |
|---|---|---|
| 1 | 创建自定义 provider（driver=vllm，中文名） | 落库成功，`is_custom=true`，`driver=vllm` |

# 第三部分：风险与待确认

## 3.1 风险

| # | 风险 | 概率 | 影响 | 等级 | 应对 |
|---|---|---|---|---|---|
| R1 | SSRF 被用于探测内网或窃取云凭证 | 3 | 5 | 15 高 | 拉黑 169.254.169.254 + 禁跨域重定向 + 记录每次测试的源/目标审计 |
| R2 | 用户填错地址导致调用挂起 | 3 | 3 | 9 中 | 超时上限 300s + 连接池隔离 |
| R3 | 各协议模型列表结构不一致导致解析失败 | 4 | 2 | 8 中 | 拉取失败引导手动填写，不阻断 |
| R4 | 自定义模型与预置模型同名，选择器混淆 | 2 | 3 | 6 低 | 选择器显示「显示名 / 模型名」二级标识 |
| R5 | 密钥明文落库 | 2 | 4 | 8 中 | 复用既有加密，禁止接口回显明文 |

## 3.2 待确认

| # | 问题 | 影响 |
|---|---|---|
| Q1 | 是否允许**普通租户**自行添加内网地址，还是需要平台超管开启开关？ | 决定 SSRF 策略松紧 |
| Q2 | 自定义服务是否需要"仅本租户可见"之外的共享能力（如平台级预置）？ | 决定 provider 归属层级 |
| Q3 | 自动拉取模型清单，需要支持哪些协议？（OpenAI 兼容的 `/v1/models` 是通用，Ollama 的 `/api/tags` 不同） | 决定拉取适配器数量 |
| Q4 | 自定义模型能否参与「默认模型」与「应用级模型」选择？ | 决定是否需要扩展模型选择器 |
| Q5 | 删除被引用服务时，是硬拦截还是软失效？ | 决定是否要引用计数 |
