# 文件解析能力：两条路的分工与实测结论

> 环境：线上 `172.30.20.51`（`ssh ecs-ragflow`），代码 `d4d6f2c`。
> 本文所有结论都是在这套环境里跑出来的，不是推断。实测脚本见文末。

## 一、先说结论：这是两件不同的事

「解析」在这个系统里有两条完全独立的链路，走错一条就会得到「明明配了却读不出内容」的错觉。

| | 文件解析助手（对话式） | 全格式解析流水线（入库式） |
|---|---|---|
| 画布类型 | `agent_canvas` | `dataflow_canvas` |
| 怎么用 | 聊天窗口里丢文件，直接问 | 绑到知识库，上传文档后自动解析入库 |
| 产出 | 一段回答 | 分片（chunk）落到知识库，可检索 |
| 文件读取时机 | run 开始**前**，转成文本塞进 `sys.files` | 解析时，走 `Parser` 组件按格式分派 |
| 音频 | ❌ 读出空字符串 | ✅ 走 ASR 真转写 |
| 视频 | ❌ 直接报错，整次运行失败 | ❌ 同样报错（后端未实现，见第三节） |
| 图片 | ✅ 送给多模态模型描述 | ✅ 本地 OCR + 视觉模型描述 |

## 二、实测结果

### 对话式：文件解析助手

配置是 `Begin(文件输入) → Agent → Message`。没有 Parser 节点——文件在进入画布前就被
`ParseAgentUploads` 解析成文本，放进 `sys.files`；LLM 组件的 `{sys.files}` 占位符
会把文本拼进提示词，图片则走 `VisualFiles` 多模态通道。

| 格式 | 结果 | 实测输出 |
|---|---|---|
| PDF | ✅ | 「最低投资金额 100 元人民币，申购费率为 0.15%」 |
| DOCX | ✅ | 「最低定投金额 100 元 / 申购费率 0.15% / 赎回确认 T+1」 |
| XLSX | ✅ | 按要求只列出基金代码 `000001`、`510050` |
| CSV | ✅ | 问费率答「0.15%」 |
| Markdown | ✅ | 按原文层次还原标题与要点 |
| PNG | ✅ | 问「这张图是什么颜色」答「这张图是红色」 |
| 音频 | ❌ | `File: huaxia.mp3 / Content: （空）` |
| 视频 | ❌ | `parse agent files: unsupported file type: video` |

两个注意点：

1. **模型必须支持 vision**。当前用 `qwen3-vl-plus`（`model_type=9`，chat+vision）。
   换成纯文本模型后，一旦上传图片会直接被 `rejectUnsupportedImages` 拒掉，整次运行失败。
2. **图片尺寸不能太小**。1×1 的图会被模型以
   `height:1 or width:1 must be larger than 10` 拒绝——这看着像解析失败，其实是图太小。

### 入库式：全格式解析流水线

结构是 `File → Parser → TokenChunker → Tokenizer`，Parser 一次配齐 14 类格式。

用一个临时知识库绑上去跑了一遍，六种文件全部 `COMPLETED`：

| 格式 | chunk 内容（原文摘录） |
|---|---|
| PDF | `Huaxia Fund minimum investment 100 CNY. Subscription fee 0.15 percent.` |
| DOCX | `华夏基金定投说明 / 本基金最低定投金额为 100 元，申购费率 0.15%。/ 赎回确认时间为 T+1 个工作日。` |
| XLSX | `<table><caption>Sheet1</caption><tr><th>基金代码</th>…` |
| PNG | `这是一张纯红色的图像，无任何可见内容。- 文字：无法辨认（无文字）…` |
| Markdown | `# 华夏基金定投 / 最低定投金额 100 元。` |
| **WAV** | `华夏基金的最低定投金额是100元，申购费率是0.15%，赎回确认时间是T+1个工作日。` |

音频那条是最有说服力的：样本是用租户自己的 `qwen3-tts-flash` 合成的语音，再喂给
`qwen-audio-3.0-asr-flash`（`model_type=4`）转写，**结果和合成文本一字不差**。
（wav 的真身是 24kHz 单声道 PCM，不是伪造的空文件。）

## 三、视频为什么不行——这是后端限制，不是配置问题

`internal/ingestion/component/media_dispatch.go` 里 `maybeDispatchVideo` 直接返回错误：

```go
// Video parsing is intentionally not implemented yet: the underlying
// video-analysis capability is pending. ...
return parser.ParseResult{}, true,
    fmt.Errorf("Parser: video parsing is not yet supported; underlying video analysis capability is pending")
```

原因是底层没有抽帧能力：OpenAI 兼容驱动只认 `image_url`（`video_url` 会被忽略），
Gemini 的 `googleMessageParts` 也会静默丢掉 `video_url`。与其拿提示词文本瞎编一段
"视频描述"，不如明确报错。

所以：**视频在当前版本任何路径都解析不了**——对话式、入库式、改参数都不行。
要支持得先实现「抽帧 → 逐帧走 image_url」或「按 provider 传原始字节」，属于功能开发。

流水线里仍然保留 `video` setup，是为了让上传视频时报出上面那句明确原因，
而不是掉进「按 UTF-8 读二进制」的乱码兜底。

## 四、怎么用

### 文件解析助手（聊天）

1. 画布列表里打开「文件解析助手」，右上角进对话。
2. 拖文件进输入框，等上传完成（会显示文件名）。
3. 直接发；或在输入框里带上要求，例如「提取所有金额」「转成 JSON」「这份合同的违约条款是什么」。

不传文件只打字时，它会提示「请上传需要我处理的文件」，不会瞎编内容。

### 全格式解析流水线（入库）

1. 新建知识库，解析方式选「使用解析流水线」，选中「全格式解析流水线」。
2. 上传文档后系统自动按这条流水线解析。
3. 已有的「音频解析」流水线只配了 audio 一类，**其它格式会掉进文本兜底**；
   换成「全格式解析流水线」才按各自格式解析。

### 脚本（都可复跑，幂等）

```bash
export RF_SECRET_KEY=... RF_ACCESS_TOKEN=...

# 建/更新两个对象
python3 scripts/build_parser_agent.py          # 对话式，--dry-run 只看 DSL
python3 scripts/build_ingest_pipeline.py       # 入库式，--dry-run 只看 DSL

# 实测
python3 scripts/build_parser_agent.py --test           # 7 个用例，含图片与"不传文件"
python3 scripts/verify_ingest_pipeline.py <pipeline_id> # 建临时库→上传→解析→读回 chunk→删库
python3 scripts/probe_agent_file_parse.py              # 只测上传链路对各类文件的原始行为
```

`verify_ingest_pipeline.py` 默认结束就删临时知识库，只有加 `--keep` 才保留。
它需要 `/tmp/probe_parse/huaxia_voice.wav` 作为音频样本，没有就跳过音频项。

## 五、排错对照

| 现象 | 原因 |
|---|---|
| 上传了文件，回答却说「看不到文件」 | 调了 `/agents/{id}/run`。这个端点不接受 `files`（handler 里硬传 nil），要用 `/agents/chat/completions` |
| 上传图片整次失败，报 `rejectUnsupportedImages` | Agent 节点绑的模型不支持 vision |
| 图片报 `width:1 must be larger than 10` | 图太小，不是解析问题 |
| 上传视频失败 | 后端未实现，见第三节 |
| 入库后音频文档 chunk 为空 | 知识库绑的是只有 audio setup 的流水线，但 `audio.vlm.llm_id` 为空且租户没有默认 ASR |
| 解析器构造失败 `image has no text source` | image 的 `ocr_enabled=false` 且 `enable_vision_enhancement=false`，两个文本源都关了 |
