# 发版验证流程 · 同义词/词条修复

> 配套报告：`docs/同义词扩写掉分排查报告_20261029.md`
> 本次发版包含两个修复：① 门槛被同义词扩写撑大导致分数反降；② 词条按原文存库、查不到分词后的问法。
> 全程在「华夏基金FAQ库」上做（`6995fa4b…`，9 条 chunk / 3 个文档）。

## 开始之前：三条硬规矩

1. **界面上有两套分数口径，别混**：
   - 「检索测试」页显示的是**百分比**（×100，两位小数）：`91.64`
   - 「变更中心 → 测试对比」显示的是**三位小数**：`0.909`
2. **参数固定**：TopK = 5，阈值 = 0.2，权重留默认（0.3）。对比两侧必须用同一套参数，否则不可比。
3. **看排名和命中条数，不要只看绝对分数**。修完之后 `term` 通道饱和（`atan` 归一化），只要命中就会有词法分，所以「命中同义词组」的问句分数会挤在 91% 附近——这是结构性的，不是新 bug。详见文末「怎么读这些数字」。

# 阶段一：不发布任何变更（先验门槛修复，不碰线上词表）

## 第一步：发版

执行 `/root/deploy.sh`，等 `ragflow-api` / `ragflow-ingestor` / `ragflow-admin` 三个服务都起来。

**三个都必须重启**（只重启 api 会让解析跑旧二进制）。

## 第二步：冒烟——先确认新二进制在跑

打开知识库 → 左侧「检索测试」→ 问题填 `什么是基金定投` → TopK 5、阈值 0.2 → 测试。

| 项 | 期望 |
|---|---|
| 第 1 名内容 | 「问题：什么是基金定投 回答：基金定投是在固定时间…」 |
| 第 1 名分数 | **91.64%**（允许 91.5~91.8） |
| 命中条数 | 5 |

这道题**不涉及任何同义词**，所以发版前后必须一模一样。
→ 如果这里就不对（分数掉到 20% 档、或第 1 名不是它），**停下**，说明发版/重启有问题，先别继续。

## 第三步：验「门槛修复」——这是主判据

依次测这 3 个问句（都只用「检索测试」，不需要发布）：

| # | 问题 | 发版前（今天） | 期望 | 说明 |
|---|---|---|---|---|
| 3.1 | `基金怎么卖出（赎回）有哪些渠道` | 第 1 名 **21.95%** | 第 1 名 **≈91.9%**，命中 5 条 | 这道题的 `赎回` 命中了现存词表组，今天被门槛压死 |
| 3.2 | `申购费率是多少` | **1 条**，21.34% | **4 条**，第 1 名 ≈91.3% | 今天另外 3 条被整条过滤（不是分低，是没召回） |
| 3.3 | `买基金` | 第 1 名 **20.93%** | 第 1 名 **≈90.9%**，命中 5 条 | 扩写词最多的一道 |

**判定**：3.1 和 3.2 是硬指标——只要这两个从 20% 档跳到 90% 档（且 3.2 从 1 条变 4 条），门槛修复就算生效。

> 注意 3.1~3.3 都属于「命中了词表组」的问句，修复后都会落到 **90% 档**，而且同组相关的 chunk 也会一起上来。这是扩写本来的效果（召回变宽），不是分数失控——判据是**第 1 名对不对**，不是分数高低。

## 第四步：验「没误伤」——4 个不含词表的问句必须一分不变

| 问题 | 发版前 | 要求 |
|---|---|---|
| `什么是基金定投` | 91.64% | 与发版前**完全一致**（±0.3） |
| `基金净值在哪里查` | 91.42% | 同上 |
| `开户需要准备什么` | 91.22% | 同上 |
| `基金分红方式有哪些` | 91.71% | 同上 |

这 4 个问句的分词结果不落在任何词表 key 上，所以修复逻辑（只在发生扩写时生效）**不应该碰它们**。

→ **任何一个偏离超过 1 个点，立即停下并告诉我**：说明修复影响了不该影响的路径。

## 第五步：先看对比，确认不再掉分（不发布）

左侧「变更中心」→ 右上「测试对比」→ 问题填 `基金是怎么买` → TopK 5、阈值 0.2 → 点「测试」。

| 项 | 发版前（今天） | 期望 |
|---|---|---|
| 原配置命中 | 5 | 5 |
| 新配置命中 | 5 | 5 |
| 同一个 chunk 的分数 | 原 **0.9089** → 新 **0.2126** | 两侧都在 **0.90 附近**，差 **< 0.02** |
| 交集平均分差 | **−0.1393** | **≈ 0.000**（−0.01 ~ +0.01） |

**这是用户最初报的那一幕**：修复前「加了词 → 同一个 chunk 从 0.909 掉到 0.213」。修复后两侧应当基本一致。

→ 如果新配置仍然掉到 0.21 档，说明门槛修复没生效，回到第二步检查。

## 第六步：发布

确认第五步通过后，「变更中心」→ 勾选那条词组变更 →「选中发布」（或「发布全部」）→ 确认。

发布后线上检索立即生效，同时词表缓存会自动重建。

## 第七步：验「词条别名」生效

回到「检索测试」→ 问题 `基金怎么买` → TopK 5、阈值 0.2 → 测试。

| 位置 | 发布前 | 发布后期望 |
|---|---|---|
| 第 1 名「问题：基金怎么买」 | 90.95% | **≈91.3%**（基本不变） |
| 第 2~5 名（基金怎么卖出 / 定投 / 分红 / 申购费率） | **20.3~21.1%** | **90.3~91.0%** |

这正是「加了『基金是怎么买』这条词条」在起作用——它被折算成 `基金买` 这个 key，让 `买基金 / 申购 / 购买基金 / 想买基金` 一起参与了扩写，所以同组相关的 chunk 也被召回了。

# 出问题了怎么办

**不要自己回滚。** 把这三样发我，我出 revert 提交给你发：

1. 哪一步、哪个问句
2. 前后两次的分数（截图最好，带上「检索测试」页的 Hybrid / Term / Vector 三列）
3. 命中条数

**Term Similarity 那一列是排障关键**：
- Term ≈ 0 而 Vector 正常 → 关键词通道被掐，是门槛侧问题
- Term ≈ 1 但排错了 → 是排序/归一化问题，与本次修复无关

# 附：怎么读这些数字

线上引擎是 Infinity，融合分 = `0.7 × term + 0.3 × vector`（权重取默认 0.3）。

- `vector` 落在 **0.68~0.72**，取决于语义相似度——它是真正在区分的部分。
- `term` 被 `atan` 归一化压得**近乎二值**：命中任何词 → 0.99 上下；一个词都不命中 → 0。

所以分数天然只有两档：**「词法命中」≈0.9 档** 和 **「纯向量」≈0.21 档**。

修复前，门槛把大量本该命中的问句误判成「不命中」，于是正确答案落到 0.21 档；
修复后它们回到 0.9 档。**分数变高不等于变松**——真正的区分力来自 `vector` 那一列。

如果想进一步拉开区分度，下一步是给 Infinity 换融合归一化方式（`atan` → `min_max` 之类）并重定阈值，那是独立一版的事。
