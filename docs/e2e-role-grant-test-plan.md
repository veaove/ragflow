- 文件级 allow/deny 的全路径（需专用测试库上传文件，记 G2）。
- 性能/并发（独立压测，记 G10）。

## 3. 权限校验口径（判定标准）

### 3.1 四个动作的定义

| 动作 | 含义 | 判定接口 | 通过标准 |
|---|---|---|---|
| **可见** | 资源出现在列表 / 授权树里 | `GET /datasets`、`/chats`、`/searches`、`/agents`、`/memories`、`/grant-tree` | 出现即可见；不出现即不可见（不区分「不存在」与「无权限」） |
| **可读** | 能打开详情、能看内容 | `GET /<kind>/:id`、文档列表、检索召回 | `code=0`；不可见时 `code≠0` 且文案不含资源信息 |
| **可写** | 能改名 / 编辑 / 上传 / 训练 | `PUT /<kind>/:id`、上传接口 | 需要该资源的 `read` 或 `edit` 授权；无授权返回 403/404 |
| **可管理** | 能删除、改可见范围、改授权、改成员角色 | `DELETE`、`PUT /grants/*`、`PUT /roles/*`、`PUT /console/members/*` | 仅租户管理层（owner / admin / 部门管理员在其范围内），**与权限矩阵无关** |

### 3.2 越权访问的预期行为（统一约定）

| 场景 | 预期 | 判定依据 |
|---|---|---|
| 资源不可见 → 读详情 | HTTP 200 + `code≠0` + `message` 含 `Resource not found` | 不泄露「资源存在」；与「不存在」同一文案（智能体目前例外，见 D6） |
| 非管理层调用管理接口 | **HTTP 403** | 拦截发生在租户/角色校验，早于资源存在性（因此打不存在的 id 也 403） |
| 请求里塞别人的租户 id | HTTP 403 + `租户不存在` | 不回落成「自己的租户」 |
| 跨租户资源 id | HTTP 403 + `租户不存在` / `Resource not found` | 不允许跨租户读取 |
| 缺失 / 伪造 token | HTTP 401 | `Missing Authorization header` / `Invalid access token` |
| 未接入排除语义的类型写 deny | HTTP 200 + `code≠0`（业务拒绝） | 配置错误先于资源校验暴露 |
| 把 owner / 创建者写进排除名单 | HTTP 200 + `code≠0` | 排除对管理层与创建者无效，写进去只会误导 |
| 分页越界（`page=0`、`page_size>200`） | `code=101` / 回落到默认 20 | 参数校验先于查询，不透传非法 LIMIT |

### 3.3 一条重要的解耦约定

**权限矩阵控制「能不能进这个功能模块」，资源授权控制「能看到哪些资源」。** member 的矩阵 25 项全勾，但对 6 类资源中的 5 类看不到任何数据 —— 这正是两者解耦的证据，也是本方案里反复验证的点（矩阵全勾不等于数据全可见）。

## 6. 执行步骤

```bash
cd e2e

# 1) 首次准备
npm install
npx playwright install chromium

# 2) 生成/刷新登录态（token 被顶掉、401 时必做）
node scripts/auth.mjs

# 3) 全量（71 条，约 2 分钟）
npx playwright test

# 4) 分组执行
npx playwright test specs/90-matrix.spec.ts      # 矩阵回归
npx playwright test specs/40-overreach.spec.ts   # 越权
npx playwright test --grep "矩阵"                # 按标题过滤

# 5) 报告
npx playwright show-report report
```

失败的用例在 `test-results/` 下留 `trace.zip`：`npx playwright show-trace <path>` 可逐帧回放。

**判读规则**：`401` 一律视为**登录态失效**（先重跑 `auth.mjs`），不得计入「拦截成功」——所有拒绝类断言都先断 `res.status() === 200`。

## 9. 风险与数据安全

| 风险 | 缓解 |
|---|---|
| 用例把线上数据写坏 | 只读基线：写接口打不存在的资源，或提交与现状相同的值；`SetGrants` 是 replace 语义，所以**任何写用例都必须先读出既有授权再原样带回去** |
| 登录态过期导致假绿 | 拒绝类断言先断 HTTP 200；401 单独识别 |
| 目标数据被管理员改动 | 用「owner 列表 − member 列表」求差集，不写死 id |
| 前端与后端版本不一致 | 结构性断言（`supports_deny`）按发版节奏转绿，不为了绿而放宽 |
| 发版窗口内的旧页面 | 前后端同批发布；`effect` 缺省时后端保留既有排除，避免老页面把排除改成允许 |
