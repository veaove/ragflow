## 四、核心矛盾（未解释）

**后端返回中文，前端链路代码正确，但创建出来的实例是英文。**

实证数据（2026-10-22 16:09:46 用户新建「学术论文助手」）：

| 对象 | DSL 字节 | 提示词 |
|---|---|---|
| 模板 `41`（en） | 9393 | `## Role & Task You are **CAJAL**…` |
| 模板 `41_zh`（zh） | 9152 | `## 角色与任务 你是 **CAJAL**…` |
| **实例「学术论文助手」** | **9680** | **`## Role & Task You are **CAJAL**…`（英文）** |

**结论：实例是用英文模板 `41` 创建的，而不是 `41_zh`。**

同类证据（「deep」15:52:55 创建）：112049 字节，内容为 `You are a Strategy Research Director…`（英文）。

## 五、排查过程与**已排除的可能**（避免重走弯路）

### 5.1 已修复的真实问题：前端 GET 传参

`agentService` 由 `registerNextServer` 构建：

```ts
// web/src/utils/register-server.ts
server[name] = (config, useAxiosNativeConfig = false) => {
  const nextConfig = useAxiosNativeConfig ? config : { data: config };
  return request({ url, method, ...finalConfig });
};
```

默认把入参包成 `{ data }`，而 `next-request` 是标准 axios，**GET 只读 `config.params`**。
必须写成 `service({ params: {...} }, true)`。

已修复于 `38d891034`。

> **注意**：仓库里有两套封装，写法不同，容易混：
> - `registerServer`（旧，umi-request）：`service({ key })`
> - `registerNextServer`（新，axios）：`service({ params: {...} }, true)`
>
> `agentService` / `llmService` / `memoryService` 用后者，`searchService` 用前者。

### 5.2 已排除：二进制不含新代码

重新编译后 MD5 与旧版**完全一致**（`f55c24387c6730a1b7de93e3b694f11d`），
说明 Go 编译是确定性的，二进制一直含新代码。**不是编译问题。**

### 5.3 已排除：nginx 丢 query

nginx `location ~ ^/api/v1 { proxy_pass http://127.0.0.1:9380; }` 不带 URI，
query 会保留。且应用日志有 `has_query: true, query_len: 7`。

### 5.4 已排除：中文模板数据错误

内容、`base_id`、`canvas_category`、`canvas_type` 全部正确。

### 5.5 **我走过的三个误判（接手人请勿重复）**

**误判一：用 DSL 字节数判断"用的哪份模板"**

我曾据此断言实例来自英文模板。但这不可靠——英文 + 绑定增量 与 中文 + 更大绑定增量
可以凑出同一个数（`111717+332 = 108485+3564 = 112049`）。
**正确做法：直接查提示词内容，不要靠长度推断。**

**误判二：把 MD5 相同当成"复制品"**

两个实例 MD5 相同（`03bca1dc…`），我判断"用户是复制已有实例"。
但确定性流程从同一模板创建两次，MD5 本就该相同。**此结论是错的。**

**误判三：用 SQL 覆盖 `dsl` 做兜底**

16:05 执行了：

```sql
UPDATE canvas_template t
JOIN canvas_template z ON z.base_id = t.id AND z.lang='zh'
SET t.dsl = z.dsl
WHERE t.lang='en' AND t.canvas_category='agent_canvas';   -- 更新 15 行
```

验证 `id=1` 已变中文。但 **16:06 重启服务后，又被改回英文**。

原因：`SeedCanvasTemplates` 在每次启动时对 `canvas_template` 做 upsert，
`DoUpdates` 包含 `dsl`，会把 JSON 文件里的英文重新写回。

> **重要结论：`canvas_template.dsl` 不能靠 SQL 改，重启即失效。
> 要改内容只能改 `internal/agent/templates/*.json` 源文件。**

### 5.6 已排除：React Query 缓存

`useFetchAgentTemplates` 的 `queryKey` 已带上语言（`[templates, 'zh']`），
`staleTime` 未设置（默认 0，挂载即重新请求）。刷新后 dump 证明返回中文。

## 十、设计意图（供接手人理解上下文）

采用**双记录**方案：每个中文模板是 `canvas_template` 里一条独立记录
（`id = 原id + "_zh"`，`base_id = 原id`，`lang = "zh"`），

- 英文请求（`lang=en` 或不传）：只返回 `lang='en'` 的记录
- 其他语言：按 `base_id` 分组，**请求语言优先、缺失回退英文**

这样翻译可以分批上线，未翻译的模板仍以英文出现而不会消失。

**已克隆的实例（`user_canvas`）是模板的快照副本，不会随模板更新**——这是有意设计
（保护用户已有修改），不是 bug。因此任何修复都需要**新建**智能体才能验证，
不能看旧实例。
