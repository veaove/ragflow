## 一、背景与目标

### 1.1 背景

基金智能客服面向公众提供基金咨询、开户引导、售后处理等服务。监管对基金销售适当性与宣传用语有明确要求（不得承诺收益、不得使用绝对化用语、须充分揭示风险）。当前系统缺少对 AI 回答内容的实时质检手段，合规风险依赖事后人工抽查，覆盖低、响应慢。

**现状痛点**：

| # | 痛点 | 影响 |
|---|---|---|
| 1 | AI 回答是否违规只能事后人工抽查 | 覆盖率不足 1%，违规内容已触达用户 |
| 2 | 无关键词规则集中配置能力 | 合规要求更新（如新增禁用词）需逐应用改提示词 |
| 3 | 命中后无提示与追溯 | 质检人员无法第一时间介入，也无法复盘 |

### 1.2 目标

| 目标 | 说明 |
|---|---|
| 集中配置 | 租户管理员可统一配置触发质检的关键词与提示信息，一处配置全局生效 |
| 实时质检 | AI 回答与用户输入实时过质检，命中即记录、即提示、可拦截 |
| 可追溯 | 命中记录保留 ≥180 天，可按规则/会话/时间检索，支持导出 |

### 1.3 成功指标与口径

| 指标 | 口径 | 目标值 |
|---|---|---|
| 质检规则配置数 | 上线 30 天内租户配置的启用规则数 | ≥ 20 条 |
| 违规内容触达用户数 | 命中「阻断」级规则且仍返回用户的回答数 | **0**（阻断必须 100% 生效） |
| 命中告警延迟 | 从命中到质检面板出现的 P95 延迟 | ≤ 2s |
| 质检开销 | 质检对聊天首包延迟的 P95 增量 | ≤ 30ms |
| 记录完整率 | 命中记录成功落库数 ÷ 实际命中数 | ≥ 99.9% |

> 「违规内容触达用户数 = 0」是硬指标：阻断级规则若有一条漏过，功能即失效。

## 二、名词与术语

| 术语 | 定义 |
|---|---|
| 质检规则 | 一组关键词 + 匹配模式 + 作用范围 + 严重级 + 动作 + 提示信息的配置单元 |
| 触发关键词 | 命中判定依据，一条规则可配多个 |
| 匹配模式 | 包含 / 全词 / 正则三种 |
| 作用范围 | AI 回答 / 用户输入 / 两者 |
| 严重级 | 提示(info) / 警告(warn) / 阻断(block) |
| 动作 | 仅记录 / 记录并告警 / 拦截并告警 |
| 提示信息 | 命中后展示给质检人员的文案；阻断级同时作为替代话术返回用户 |
| 阻断 | 命中后该回答不返回用户，替换为提示信息 |
| 质检旁路 | 异步记录与推送链路，独立于聊天主链路，故障不影响对话 |

## 三、需求范围

### 3.1 本期包含（V1.0）

| 模块 | 内容 |
|---|---|
| 应用内质检规则 | 在聊天应用设置页与对话流编辑器设置面板内配置规则（规则绑定到该应用，仅本应用生效） |
| 实时质检 | AI 回答与用户输入实时匹配、增量匹配去重、阻断拦截与替代话术、命中推送 |
| 质检看板 | 实时命中事件流、进行中会话列表 |
| 命中记录 | 查询（多条件筛选）、详情（含上下文）、导出 CSV |
| 权限 | 租户管理员 / 质检员 / 普通成员三级 |
| 系统配置 | 质检总开关、规则上限、记录保留期 |

**生效入口覆盖范围**（两条执行链路，分别挂点）：

| 链路 | 入口 | 阻断 |
|---|---|---|
| **链路 1** · Chat Pipeline（`AsyncChat`） | 聊天页、外部 bot、OpenAI 兼容接口、chatbots 分享/嵌入页 | ✅ |
| **链路 2** · Agent 画布运行时（`RunAgent`） | chatflows 公开 API、workflows 公开 API、agentbots 分享/嵌入页、Webhook 触发 | 仅 Chatflow |
| **链路 2** · 调试（`trigger_type=debug`） | 编辑器试运行 | ❌ 只记录，不阻断不告警 |

> 为什么分两条：chatflow / workflow 走 `RunAgentAsApp`（agent 画布运行时），
> 与聊天页走的 `AsyncChat`（chat pipeline）是两套独立执行链路，只在一边挂点会漏掉另一半入口。
>
> Workflow 为什么不阻断：其输出是结构化 JSON、供下游系统消费，替换文本会破坏调用方数据契约，
> 故 Workflow 命中只记录 + 告警。

### 3.2 本期不包含

| 能力 | 计划版本 | 原因 |
|---|---|---|
| 租户级全局规则（一处配多处生效） | V1.1 | V1.0 按用户确认的信息架构做应用级；全局规则待验证需求后评估 |
| 质检统计看板（趋势/占比图表） | V2.0 | MVP 先保证可用，再补分析 |

| 坐席侧质检提示 | 待定 | RAGFlow 无坐席工作台，需外部系统对接或新建，工作量 +8~12 人日 |
| 跨应用规则复制/模板 | V1.1 | 多应用要配相同规则时，提供从已有应用复制 |

## 四、方案对比与选型说明

| 方案 | 实现成本 | 开发复杂度 | 用户体验 | 风险 | 上线时间 | 综合评价 |
|---|---|---|---|---|---|---|
| A. 画布节点分流（零改造） | 无 | 低 | 差 | 低 | — | ❌ 非集中配置、非实时拦截、无看板 |
| B. 单通道同步质检 | 低 | 低 | 中 | 中（阻塞主链路） | 快 | 备选 |
| **C. 双通道（同步拦截 + 异步记录）** | 中 | 中 | 好 | 低 | 中 | ✅ **推荐** |
| D. 外挂独立质检网关 | 高 | 高 | 好 | 高（新增单点） | 慢 | ❌ 过度设计 |

**推荐 C 的理由**：

1. 阻断必须在内容到达用户前完成，只能同步；记录与推送不阻塞对话，走异步
2. `AsyncChat` 内部单一挂点覆盖全部 3 个聊天入口（主会话 / 外部 bot / OpenAI 兼容）
3. 异步旁路复用现有 NATS，无新增基础设施
4. 质检故障被隔离在旁路，不影响对话可用性

## 五、用户角色与使用场景

### 5.1 用户角色

| 角色 | 身份 | 核心目标 |
|---|---|---|
| 租户管理员 | 平台运营/合规负责人 | 配置并维护质检规则，把控全局合规水位 |
| 质检员 | 质检团队 | 实时发现命中事件，介入处置，复盘记录 |
| 应用搭建者 | 对话流/聊天应用的搭建者 | 在自己应用内配置质检规则（只管本应用），不可见他人应用的规则与全局看板 |

### 5.2 用户故事

**US-01 规则配置**

> 作为租户管理员，我想要统一配置「禁止承诺收益」的关键词与提示信息，以便新增合规要求时一处修改全局生效。

验收标准：
- Given 已登录且有租户管理员权限，When 新建规则并填写关键词「保本/稳赚」、阻断级、提示信息，Then 规则保存后立即对全部应用会话生效
- Given 规则已启用，When 任意应用产生含「保本」的 AI 回答，Then 该回答被拦截并替换为提示信息

**US-02 实时发现**

> 作为质检员，我想要在命中发生时立刻看到事件与提示信息，以便第一时间判断是否需要介入。

验收标准：
- Given 质检面板已打开，When 某会话命中警告级规则，Then 2 秒内面板出现该事件，含命中文本、上下文、提示信息

**US-03 追溯复盘**

> 作为质检员，我想要按规则和时间检索历史命中记录并导出，以便完成合规复盘与留痕。

验收标准：
- Given 已进入命中记录页，When 按规则「禁止承诺收益」+ 时间范围筛选，Then 列表仅显示符合条件的记录，导出 CSV 内容与列表一致

### 5.3 主流程

```
管理员配置规则 → 保存生效
                      ↓
用户/应用产生对话 → 实时质检匹配 → 未命中 → 正常返回
                                    ↓ 命中
                              判定严重级
                       ┌──────────────┼──────────────┐
                    提示/警告                    阻断
                       ↓                          ↓
              回答正常返回用户            回答不返回用户
              异步记录+推送              替换为提示信息
                                         异步记录+推送
                      ↓                          ↓
                质检面板 ←──────────────── 命中记录（180 天）
```

## 六、功能需求

### FR-01 应用内质检规则配置

| 编号 | 需求 | 业务规则 | 验收标准 |
|---|---|---|---|
| FR-01-00 | 配置入口与绑定 | 规则入口在**聊天应用设置页**（「质检规则」Tab）与**对话流编辑器设置面板**（「质检规则」区块）；新建时自动绑定到当前应用，仅本应用生效 | Given 在「基金问答助手」设置内新建规则，When 保存，Then 该规则只对基金问答助手生效；Given 在「开户引导助手」对话流新建，Then 不影响基金问答助手 |
| FR-01-01 | 新建规则 | 名称必填（≤50 字）；关键词必填且 ≤50 个；提示信息必填 | Given 填写完整，When 保存，Then 规则出现在列表且状态为启用 |
| FR-01-02 | 关键词多值输入 | 回车或逗号分隔；自动去重；忽略空值；单条规则上限 50 | Given 输入「保本,保本,稳赚」，Then 保存后仅保留 2 个词 |
| FR-01-03 | 匹配模式 | 包含（默认）/ 全词 / 正则；正则需校验合法性 | Given 选正则 `保本.{0,4}收益`，Then 「保本高收益」命中；Given 正则语法错误，Then 保存被拒并提示 |
| FR-01-04 | 作用范围 | AI 回答 / 用户输入 / 两者，默认 AI 回答 | Given 选「用户输入」，When AI 回答含关键词，Then 不记录不拦截 |
| FR-01-05 | 严重级与动作 | 三档：提示·仅记录 / 警告·记录并告警 / 阻断·拦截并告警；默认警告 | Given 选阻断，When 命中，Then 回答不返回用户 |
| FR-01-06 | 提示信息 | 必填 ≤500 字；质检面板展示；阻断级同时作为替代话术 | Given 命中阻断规则，Then 用户看到的是提示信息文案 |
| FR-01-07 | 编辑规则 | 全部字段可改；修改后立即生效，无需重启 | Given 修改关键词，When 保存，Then 下一次对话即按新规则匹配 |
| FR-01-08 | 启停 | 单条规则可启停；停用后不参与匹配，历史记录保留 | Given 停用规则 A，When 再命中，Then 不产生新记录 |
| FR-01-09 | 删除 | 需二次确认；删除后规则不再生效，历史记录保留 | Given 确认删除，Then 列表移除该规则，命中记录仍可查 |
| FR-01-10 | 规则上限 | 单租户启用+停用合计 ≤200 条（可配） | Given 已有 200 条，When 新建，Then 被拒并提示上限 |
| FR-01-11 | 规则测试 | 编辑时输入测试文本，实时高亮命中位置并预告动作 | Given 输入含关键词文本，Then 显示命中数量、高亮位置、将执行的动作 |

### FR-02 实时质检

| 编号 | 需求 | 业务规则 | 验收标准 |
|---|---|---|---|
| FR-02-01 | AI 回答质检 | 每个流式 delta 过质检；`fullAnswer` 兜底匹配 | Given 关键词被拆到两个 delta，Then 兜底匹配仍命中并记录 |
| FR-02-02 | 用户输入质检 | 消息进入时匹配一次 | Given 用户输入含关键词，Then 记录一条，范围标记为用户输入 |
| FR-02-08 | Chatflow 阻断 | Chatflow 的 `message` 事件命中阻断级时，替换为提示信息 | Given Chatflow 命中阻断，Then 用户收到替代话术 |
| FR-02-09 | Workflow 不阻断 | Workflow 的 End 输出命中只记录 + 告警，不改写输出 | Given Workflow 命中阻断规则，Then 返回给调用方的 JSON 与原文一致 |
| FR-02-10 | 调试运行豁免 | `trigger_type=debug` 时只记录，不阻断不告警 | Given 编辑器试运行命中阻断规则，Then 画布正常显示原文 |
| FR-02-11 | API Key 调用归属 | 记录 `tenant_id` 为画布 owner，与调用方身份解耦 | Given 用 API Key 调 chatflow，Then 按画布 owner 的规则集质检 |
| FR-02-03 | 增量匹配去重 | 同一规则在同一会话对同一位置只报一次 | Given 一段话出现两次「保本」，Then 仅记录 1 条 |
| FR-02-04 | 阻断拦截 | 命中阻断级时该 delta 不发给用户；按提示信息生成替代话术 | Given 命中阻断，Then 用户看到替代话术，原文不出现 |
| FR-02-05 | 实时推送 | 警告/阻断级经 NATS 推送质检面板 | Given 命中警告，Then P95 ≤2s 面板出现 |
| FR-02-06 | 旁路隔离 | 质检服务异常不得影响聊天 | Given 质检服务宕机，Then 对话正常，仅无记录 |
| FR-02-07 | 总开关 | `qc.enabled` 关闭时全部规则不生效 | Given 关闭开关，When 命中，Then 不记录不拦截不推送 |

### FR-03 质检看板与记录

| 编号 | 需求 | 业务规则 | 验收标准 |
|---|---|---|---|
| FR-03-01 | 进行中会话列表 | 展示当前有活跃会话的应用，含命中数徽标 | Given 有新命中，Then 徽标数字 +1 |
| FR-03-02 | 实时事件流 | 按时间倒序展示命中事件，含命中文本高亮、上下文、提示信息 | Given 打开面板，Then 看到最近事件；Given 新事件，Then 自动追加 |
| FR-03-03 | 记录查询 | 按时间范围/规则/范围/严重级/会话 ID 组合筛选，分页 | Given 选阻断级，Then 仅显示阻断记录 |
| FR-03-04 | 记录详情 | 展示命中文本、前后各 50 字上下文、规则名、提示信息、动作、会话跳转链接 | Given 打开详情，Then 信息完整且可跳转到会话 |
| FR-03-05 | 导出 | 按当前筛选条件导出 CSV，需质检员及以上权限 | Given 导出，Then CSV 行数与筛选结果一致 |
| FR-03-06 | 保留期 | 记录保留 ≥180 天（可配），到期自动清理 | Given 配置 180 天，Then 181 天前的记录不可查 |

|---|---|---|---|

## 八、业务流程与状态流转

### 8.1 质检规则状态机

```
[草稿] --保存--> [启用] --停用--> [停用] --启用--> [启用]
   |                |                  |
   └── 放弃 ──→  [已删除] ←── 删除 ────┘
```

| 状态 | 允许操作 |
|---|---|
| 启用 | 编辑、停用、删除、测试 |
| 停用 | 编辑、启用、删除、测试 |
| 已删除 | 无（记录保留） |

### 8.2 命中记录生命周期

```
命中产生 → [待处理] --质检员查看--> [已查看] --导出/复盘--> [已归档]
                                                              ↓
                                                    保留期满 → [已清理]
```

## 九、数据与埋点需求

| 最小化 | 仅记录命中文本与必要上下文，不记录完整对话 |

## 十一、异常处理清单

| 场景 | 表现 | 恢复方式 |
|---|---|---|
| 关键词为空 | 保存按钮置灰，提示「请至少添加一个关键词」 | 补全后保存 |
| 正则语法错误 | 保存被拒，定位到正则输入框并提示错误原因 | 修正正则 |
| 关键词超上限 | 输入被拒，提示单条规则上限 50 | 删除多余词或新建规则 |
| 规则数超上限 | 新建被拒，提示租户上限 200 | 删除无用规则或申请提额 |
| 质检服务不可用 | 对话正常，无记录；看板显示「质检服务异常」 | 自动重连；恢复后补推断开期间事件 |
| NATS 推送失败 | 记录已落库，看板缺实时事件 | 刷新页面从库加载 |
| 阻断替换话术为空 | 使用系统默认兜底话术 | 配置提示信息 |
| 跨租户访问 | 返回 404 | — |
| 无权限访问 | 返回 403，引导申请权限 | — |
