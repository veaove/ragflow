## 一、背景与目标

### 1.1 背景

华夏基金智能客服当前基于 RagFlow 的 FAQ 解析能力维护两套知识库：**基金 FAQ 知识库**（业务问答）与**寒暄知识库**（问候、转人工、情绪安抚）。FAQ 问答对以 `问题：xxx \t 回答：yyy` 的形式存储为 chunk，检索时依赖全文检索与向量召回。

实际运营中，客服团队遇到三个具体问题：

1. **用户的说法和标准问对不上**。用户说「钱什么时候退」「退款要等几天」，标准问是「赎回基金多久到账」；说「50ETF」，标准问是「华夏上证 50ETF」。现有知识库没有同义词、近义词、专有词别名的管理入口，词表只能改服务器文件并重启，且内置词库对基金场景没有覆盖。
2. **相似问靠人工想，覆盖不全**。一个标准问通常需要 3~8 条相似问，20 个问答对就是上百条，纯手工维护成本高，且容易漏掉高频口语说法。
3. **改完不敢确认效果，也不敢直接上线**。相似问与同义词都会直接影响召回排序，但现有检索测试页只能测「当前已生效」的配置，无法回答「改完之后会变成什么样」。运营只能凭感觉发布，改坏了要等用户投诉才发现。

### 1.2 目标

| 目标 | 说明 | 衡量方式 |
|---|---|---|
| 降低词表维护门槛 | 业务人员可在页面上维护同义词、近义词、专有词别名，无需改文件、无需重启 | 全流程无研发介入即可完成一次词表变更 |
| 降低相似问维护成本 | 支持基于「现有问答 + 提示词」批量生成候选，人工勾选后采纳 | 单次批量生成可覆盖 ≥80% 的问答对；人工采纳率可观测 |
| 变更可验证 | 修改后不直接生效，先进入待生效区；测试对比展示「原配置 vs 新配置」的问答差异 | 发布前 100% 变更经过测试对比；测试结果可保存、可追溯 |
| 变更可回退 | 待生效变更可单项撤销、可全部放弃；发布后保留变更记录 | 任意一次变更可在变更中心定位到操作人、时间、前后值 |

### 1.3 非目标（本期不做）

- **不做整个知识库副本**。本期采用「配置级暂存 + 增量测试沙箱」，只沙箱受影响的 chunk，不复制全库。
- **不做自动发布**。所有变更必须人工测试确认后手动发布。
- **不做问答链路（LLM 生成答案）的对比**。本期对比的是「检索层召回了哪些问答对」，不对比最终生成话术。
- **不做跨租户词表共享**。词表作用域限定在「当前知识库」与「当前租户全局」两级。
- **不做检索准确率的绝对指标**。系统当前没有线上检索日志与人工标注，本期只做同一批测试问题下的相对对比。

> **假设（可推翻）**：寒暄知识库与基金 FAQ 知识库使用同一种 FAQ 解析类型（`qa`），因此词表与相似问能力对两者通用。若寒暄库使用其他解析类型，需在范围中单独说明。

## 二、名词与术语

| 术语 | 定义 |
|---|---|
| 标准问 | FAQ 问答对中的「问题」，一个标准问对应一个答案 |
| 相似问 | 挂在标准问下的其他用户问法，用于提升该问答对的召回覆盖面 |
| 同义词 / 近义词 | 一组指向同一语义的词，用于**查询扩展**（用户 query 中的词扩展为同组其他词） |
| 专有词汇表 | 实体别名表，把产品全称、简称、别名映射到同一个标准词，用于**实体归一** |
| 作用域 | 词表的生效范围：`当前知识库` / `租户全局` |
| 待生效变更 | 用户完成编辑但尚未发布的修改，存在暂存区，不影响线上检索 |
| 变更集 | 一次编辑会话中累积的若干待生效变更的集合 |
| 原配置 | 线上当前生效的配置（已发布的同义词、专有词、相似问） |
| 新配置 | 原配置 + 当前待生效变更后的配置 |
| 测试沙箱 | 为测试对比临时构建的检索环境，仅包含受影响的 chunk，测试后销毁 |
| 命中归因 | 指出某条召回是由哪条相似问、哪个同义词/别名触发的 |

## 三、需求范围

### 3.1 本期包含

| 模块 | 包含内容 |
|---|---|
| 词表管理 | 同义词/近义词组的新增、编辑、删除、批量导入；专有词汇表的新增、编辑、删除、批量导入；作用域设置 |
| 相似问管理 | 按问答对查看/编辑相似问；批量导入；AI 批量生成候选并人工勾选 |
| 变更暂存 | 所有编辑进入待生效区；变更中心列表；单项撤销、全部放弃 |
| 测试对比 | 多问题输入；原配置 vs 新配置并排对比；查询扩展对比；命中归因；差异摘要；测试记录保存 |
| 发布 | 发布前校验；发布执行；发布记录 |

### 3.2 本期不包含

- 知识库整体副本与审核流（沿用已有设计文档，本期不做）
- 相近知识点检测与去重
- 问答层（LLM 生成答案）对比
- 检索参数（阈值、权重）的版本化管理
- 词条级权重调节（本期同组词等权）

## 四、方案对比与选型说明

### 4.1 核心问题：如何做到「改完不生效，测试后再发布」

| 方案 | 实现成本 | 开发复杂度 | 用户体验 | 风险 | 上线时间 | 综合评价 |
|---|---|---|---|---|---|---|
| A. 配置级暂存 + 增量测试沙箱（推荐） | 中 | 中 | 好：编辑即暂存，测试秒级 | 中：需改造检索测试链路 | 中 | **推荐** |
| B. 知识库整体副本 + 审核发布 | 高 | 高 | 中：需先建副本，流程重 | 高：全库复制成本、索引冲突 | 慢 | 备选，适合大规模调优 |
| C. 直接生效 + 事后回滚 | 低 | 低 | 差：改坏即事故 | 高：线上受影响 | 快 | 不推荐 |

**推荐结论：方案 A。**

理由：
1. 本期三条需求的核心是「改完先看效果再决定」，不是「多人审核发布流程」。方案 A 的暂存 + 测试正好匹配，不需要引入副本生命周期与审核角色。
2. 相似问不影响向量（RagFlow 现有 embedding 字段为 `text`，不含 `question_kwd`），因此测试沙箱只需重算 BM25 token，不需要重跑 embedding，成本远低于全库副本。
3. 方案 B 需要处理 ES 单索引 `_id = chunk_id` 的覆盖风险（副本复用 chunk_id 会覆盖生产数据），工程风险显著高于 A。
4. 方案 C 无法满足「不能直接生效」的硬性要求，直接排除。

**演进路径**：本期做 A；当客户出现「多人审核、按版本回滚、跨库灰度」诉求时，再演进到 B（触发条件：单次变更涉及的 chunk 超过 500 条，或需要审批角色）。方案 A 的变更集数据结构可直接被 B 复用。

### 4.2 测试对比的技术实现选型

| 方案 | 准确性 | 耗时 | 适用 |
|---|---|---|---|
| 查询扩展对比（仅同义词） | 高（就是最终 query） | 毫秒级 | 同义词/专有词变更 |
| 增量测试沙箱（受影响 chunk 重建 BM25） | 高（与发布后一致） | 秒级（≤50 chunk） | 相似问变更 |
| 候选重排（live top-N 重新打分） | 中（无法发现新召回） | 毫秒级 | 降级方案 |

**推荐**：同义词/专有词走「查询扩展对比」；相似问走「增量测试沙箱」；当沙箱构建超时或失败时降级为「候选重排」，并在界面明确标注「降级结果，仅供参考」。

## 五、用户角色与使用场景

### 5.1 角色

| 角色 | 职责 | 权限 |
|---|---|---|
| 知识库运营（主要用户） | 维护词表与相似问、发起测试、发布变更 | 编辑、测试、发布当前知识库 |
| 客服主管 | 抽查变更效果、确认发布 | 查看、测试、发布 |
| 系统管理员 | 审计变更、处理跨租户问题 | 只读全部，可强制回滚 |
| 算法/研发 | 配置提示词模板、排查召回问题 | 只读 + 提示词模板配置 |

### 5.2 用户故事

**US-01 维护同义词**

作为知识库运营，我想要把「退款、退钱、退费」配置成一组同义词，指向标准问「赎回基金多久到账」，以便用户用口语说法也能被正确召回。

验收标准：
- Given 我打开了词表管理页，When 我新增词组「退款类说法」并填入 3 个词条，Then 该词组出现在列表中，状态为「待生效」。
- Given 词组已保存为待生效，When 我查看线上检索，Then 线上结果不受影响。

**US-02 维护专有词**

作为知识库运营，我想要把「50ETF」「上证 50」「华夏 50」映射到标准词「华夏上证 50ETF」，以便用户说简称时能召回产品问答。

验收标准：
- Given 专有词汇表中存在「华夏上证 50ETF」，When 我新增别名「华夏 50」，Then 变更进入待生效区。
- Given 变更已发布，When 我搜索「华夏 50 能买吗」，Then 召回「华夏上证 50ETF」相关问答对。

**US-03 批量生成相似问**

作为知识库运营，我想要选中「基金 FAQ 知识库」全库，用一段提示词让模型为每个标准问生成 3 条相似问，以便快速补齐口语说法。

验收标准：
- Given 我选择了全库与提示词，When 我点击开始生成，Then 页面展示生成进度，且生成过程不阻塞其他操作。
- Given 生成完成，When 我查看候选列表，Then 每条候选可单独勾选，未勾选的不会进入待生效区。
- Given 我勾选了 38 条并保存，Then 变更中心出现一条「相似问批量新增（38 条）」记录。

**US-04 测试对比**

作为知识库运营，我想要在发布前用 3 个真实用户问题分别跑「原配置」和「新配置」，看到两边召回的问答与分数差异，以便判断这次改动是否值得发布。

验收标准：
- Given 我有 3 项待生效变更，When 我打开测试对比并输入 3 个问题，Then 每个问题下并排展示原配置与新配置的 Top-K 结果。
- Given 某个问题在新配置下新增召回了一条问答，When 我查看对比结果，Then 该条被高亮标注「新增召回」并显示分数变化。
- Given 某个问题的新配置结果出现明显异常召回，When 我查看结果，Then 我可以选择放弃变更而不发布。

**US-05 放弃变更**

作为知识库运营，我想要在测试后发现改动效果不好时一键放弃全部变更，以便线上保持原样。

验收标准：
- Given 变更中心有 3 项待生效变更，When 我点击全部放弃并确认，Then 3 项变更被标记为已放弃，线上检索不受影响。

## 六、功能需求

> 编号规则：`FR-模块-序号`。每条需求含业务规则与验收标准，验收标准可被测试用例直接引用。
> 状态词统一：**必须（shall）** / **应该（should）** / **可以（may）** / **禁止（must not）**。

### FR-01 词表管理 · 同义词 / 近义词

| 编号 | 需求 | 业务规则 | 验收标准 |
|---|---|---|---|
| FR-01-01 | 查看词组列表 | 列表必须展示：词组名称、标准词、同义词、作用域、词条数、更新时间、状态、操作。默认按更新时间倒序。 | Given 进入词表管理，Then 展示同义词 Tab，列表含上述字段，分页默认 10 条/页。 |
| FR-01-02 | 新增词组 | 词组名称、类型、作用域、标准词、至少 1 个词条为必填；同名同作用域禁止重复创建；单组词条上限 200。 | Given 填写完整且不重复，When 保存，Then 生成一条「待生效」变更。 |
| FR-01-03 | 编辑词组 | 支持修改名称、标准词、词条、作用域、备注；保存后生成待生效变更，不直接改线上。 | Given 修改词条并保存，Then 列表状态变为「待生效」，线上检索无变化。 |
| FR-01-04 | 删除词组 | 删除必须二次确认；删除同样进入待生效区，发布后才真正删除。 | Given 删除一个已生效词组，Then 状态变为「待生效（删除）」，发布后列表中移除。 |
| FR-01-05 | 批量导入 | 支持 `.xlsx` / `.csv`；模板列为「词组名称、标准词、词条（逗号分隔）、作用域、备注」；单次最多 2000 行；导入前必须校验并展示错误行。 | Given 上传含 3 行错误的文件，Then 展示错误行号与原因，正确行可选择性导入。 |
| FR-01-06 | 作用域设置 | 作用域必须为「当前知识库」或「租户全局」；租户全局词表对所有知识库生效，知识库级优先级高于全局。 | Given 同一词同时存在于全局与知识库词表，Then 检索时使用知识库级词表。 |

### FR-02 词表管理 · 专有词汇表

| 编号 | 需求 | 业务规则 | 验收标准 |
|---|---|---|---|
| FR-02-01 | 查看专有词列表 | 列表必须展示：标准词、类型（基金产品/指数/机构/业务术语）、别名、所属领域、作用域、状态、操作。 | Given 切换到专有词汇表 Tab，Then 展示上述字段。 |
| FR-02-02 | 新增 / 编辑专有词 | 标准词、类型、至少 1 个别名为必填；同一作用域下标准词唯一。 | Given 新增「华夏上证 50ETF」，Then 生成待生效变更。 |
| FR-02-03 | 别名归一 | 检索时组内任一词命中，都必须扩展出标准词；扩展权重不得高于原词。 | Given 用户 query 含「华夏 50」，Then 扩展词包含「华夏上证 50ETF」。 |
| FR-02-04 | 批量导入 / 导出 | 支持导入与导出当前词表；导出文件可再次导入且不产生重复。 | Given 导出后原样导入，Then 不新增重复词条，只更新未变化项。 |

### FR-03 相似问管理

| 编号 | 需求 | 业务规则 | 验收标准 |
|---|---|---|---|
| FR-03-01 | 查看问答对与相似问 | 列表必须展示：标准问、答案摘要、相似问、来源文档、状态、操作；支持按文档、状态、关键词筛选。 | Given 进入相似问管理，Then 默认展示当前知识库全部问答对，含相似问数量与预览。 |
| FR-03-02 | 手工增删改相似问 | 单条问答对可增删改相似问；每条相似问必须非空、去首尾空格、同一问答对内去重；单条问答对建议 3~8 条，超过 20 条给出提示但不阻断。 | Given 新增一条重复相似问，Then 提示「已存在」且不保存。 |
| FR-03-03 | 相似问批量导入 | 模板列为「标准问、相似问」；标准问必须能在知识库中精确匹配，匹配不到的行标为错误。 | Given 导入 10 行，其中 2 行标准问不存在，Then 8 行成功、2 行报错。 |
| FR-03-04 | 编辑不直接生效 | 所有相似问修改必须进入待生效区。 | Given 修改相似问，Then 状态为「待生效」，线上检索不变。 |

### FR-04 相似问智能生成（AI 专项）

| 编号 | 需求 | 业务规则 | 验收标准 |
|---|---|---|---|
| FR-04-01 | 选择生成范围 | 支持全库、按文档、仅无相似问的问答对、当前选中；必须展示预计处理的问答对数量。 | Given 选择「仅无相似问」，Then 显示预计处理 3 条。 |
| FR-04-02 | 提示词配置 | 必须提供默认提示词模板，可修改；修改仅影响本次生成；提示词必须包含「只输出相似问、每行一条」的输出约束。 | Given 修改提示词并生成，Then 本次生成使用新提示词，默认模板不变。 |
| FR-04-03 | 异步生成与进度 | 生成必须异步执行，页面展示「已完成 N / 总数」进度；生成过程中允许关闭弹窗，任务在后台继续。 | Given 关闭生成弹窗，Then 重新进入可看到任务仍在进行或已完成。 |
| FR-04-04 | 候选勾选 | 生成结果为候选列表，默认勾选高置信项，用户可逐条取消；未勾选的不进入待生效区。 | Given 生成 60 条候选、默认勾选 38 条，When 保存，Then 只新增 38 条。 |
| FR-04-05 | 去重与质量过滤 | 生成结果必须与标准问、已有相似问去重；空结果、超长（>100 字）、含答案中不存在的事实性内容应被过滤或标注。 | Given 生成结果与已有相似问重复，Then 该条不出现在候选中。 |
| FR-04-06 | 失败与降级 | LLM 调用失败必须可重试；单条失败不影响整体；失败项在结果中标红并支持重试。 | Given 10% 的问答对生成失败，Then 其余成功项可正常勾选，失败项显示重试按钮。 |

**AI 功能六模块专项（相似问生成）**

| 模块 | 本需求的具体要求 |
|---|---|
| 任务定义 | 谁：知识库运营；何时：发现召回覆盖不足时；基于什么：知识库内已有标准问与答案 + 运营填写的提示词；做什么：为每个标准问生成若干条用户可能使用的相似问；帮到哪一步：**只出候选，不自动采纳**，最终由人工勾选 |
| 输入契约 | 标准问（必填）、答案（必填，用于约束不引入答案外信息）、提示词（默认模板 + 本次覆盖）、生成条数（3/5/8/10）、模型（租户默认）；缺失答案的问答对跳过并记录；答案超长时截断至 2000 字并标注 |
| 输出契约 | 结构化列表：`{chunk_id, standard_question, candidates:[{text, confidence}]}`；每条相似问 ≤100 字、单行、不得含编号；禁止输出解释性文字；候选必须与标准问、已有相似问去重 |
| 质量标准与验收样本 | 覆盖 200 个问答对的评测集，人工评审「可用相似问占比」≥60%；重复率 ≤5%；事实性错误（引入答案外信息）率 ≤1%；验收样本必须覆盖：正常问答、答案极短、答案含表格、寒暄类、标准问本身已很口语化 |
| 异常降级与人工接管 | LLM 超时/限流：重试 2 次后标记失败，保留已完成部分；模型不可用：提示「当前模型不可用，可改用手工编辑」；生成质量差：用户可全部取消后重新生成；所有情况均不自动写入 |
| 行为约束三层 | **Always do**：去重、过滤空/超长、标注置信度；**Ask first**：任何写入待生效区前必须人工勾选；**Never do**：不得把生成内容直接写入线上、不得基于答案外的知识编造相似问、不得绕过敏感词过滤 |
| 反馈与版本闭环 | 记录每个候选的 `adopted/rejected`、生成批次、模型版本、提示词版本、知识版本；支持按批次复盘「采纳率」；每条已采纳相似问可追溯到来源批次 |

| FR-05-01 | 编辑进入暂存 | 词表、专有词、相似问的所有增删改必须写入待生效区，禁止直接改线上。 | Given 任意编辑保存，Then 线上检索结果不变，变更中心出现记录。 |

| FR-06-08 | 测试参数 | 必须支持 Top K、相似度阈值、关键词权重、是否启用 Rerank；默认值与知识库配置一致。 | Given 知识库配置阈值为 0.3，Then 测试页默认显示 0.3。 |

## 八、业务流程与状态流转

### 8.1 主流程：一次完整的调优

```
运营发现召回问题
   │
   ▼
① 编辑词表 / 专有词 / 相似问
   │  （或：批量生成相似问 → 勾选候选）
   ▼
② 写入待生效区（变更中心可见，线上不受影响）
   │
   ▼
③ 点击「测试对比」
   │  ├─ 输入 1~10 个真实问题
   │  ├─ 跑原配置与新配置
   │  └─ 查看新增/消失/排名/分数差异
   │
   ├── 效果符合预期 ──► ④ 发布 ──► 线上生效
   │
   └── 效果不符合 ──► ⑤ 放弃 / 继续调整 ──► 回到 ①
```

### 8.2 状态机

**变更项状态**

| 当前状态 | 触发事件 | 目标状态 | 说明 |
|---|---|---|---|
| （新建） | 保存编辑 | 待生效 | 写入待生效区 |
| 待生效 | 发布成功 | 已生效 | 线上生效 |
| 待生效 | 单项撤销 / 全部放弃 | 已放弃 | 线上不变 |
| 待生效 | 发布失败 | 待生效 | 保留，修复后可重试 |
| 已生效 | 再次编辑 | 待生效（新变更） | 生成新变更项，原变更项归档 |
| 已放弃 | — | 终态 | 不可恢复，需重新编辑 |

**测试沙箱状态**

| 状态 | 说明 |
|---|---|
| 构建中 | 正在为受影响 chunk 重建 BM25 |
| 就绪 | 可执行对比 |
| 已销毁 | 测试结束或超时自动清理 |

**发布状态**

| 状态 | 说明 |
|---|---|
| 校验中 | 校验对象存在性与冲突 |
| 发布中 | 原子写入 |
| 成功 | 全部生效 |
| 失败并回滚 | 任一失败，全部回滚 |

### 8.3 发布冲突处理

- 发布前逐条比对变更项的「变更前值」与线上当前值。
- 若不一致，说明期间有人改过同一对象：该条**拒绝合并**，其余条正常发布，并单独列出冲突条目。
- 冲突条目保留在待生效区，用户可选择「覆盖」或「基于最新值重新编辑」。

## 十、权限与安全

### 10.1 权限矩阵

| 操作 | 知识库运营 | 客服主管 | 系统管理员 | 算法/研发 |
|---|---|---|---|---|
| 查看词表 / 相似问 | ✅ | ✅ | ✅ | ✅ |
| 编辑词表 / 相似问 | ✅ | ✅ | ❌ | ❌ |
| 批量生成 | ✅ | ✅ | ❌ | ❌ |
| 测试对比 | ✅ | ✅ | ✅ | ✅ |
| 发布变更 | ✅ | ✅ | ❌ | ❌ |
| 放弃变更 | ✅ | ✅ | ❌ | ❌ |
| 查看审计 | 本库 | 本库 | 全部 | 本库 |
| 强制回滚 | ❌ | ❌ | ✅ | ❌ |

### 10.2 安全规则

- 所有接口必须校验 `tenant_id` + `kb_id` 归属；越权与不存在统一返回「不存在」，防止跨租户探测（沿用现有同义词模块的处理方式）。
- 待生效变更仅创建人可见可编辑；客服主管可查看本库全部变更但不得修改他人变更。
- 提示词与生成内容不得包含个人信息；生成结果必须经敏感词过滤后展示。
- 发布操作必须二次确认，确认弹窗列出将影响的对象数量。
- 测试沙箱必须与生产索引隔离，测试结束立即销毁；禁止把沙箱数据写入生产索引。

## 十一、异常处理清单

| 场景 | 处理 | 用户提示 |
|---|---|---|
| 词条为空 / 全为空格 | 阻止保存 | 「词条不能为空」 |
| 词组名重复 | 阻止保存 | 「同一作用域下已存在同名词组」 |
| 单组超过 200 词 | 阻止保存 | 「单组最多 200 个词条」 |
| 导入文件格式错误 | 阻止导入 | 「请使用模板文件，支持 .xlsx / .csv」 |
| 导入行标准问不存在 | 跳过该行，汇总错误 | 「第 3、7 行标准问不存在，已跳过」 |
| 相似问重复 | 阻止保存该条 | 「该相似问已存在」 |
| 生成任务超时 | 标记失败，保留已完成部分 | 「部分问答对生成超时，可重试」 |
| LLM 返回空 | 该条标记失败 | 「未生成有效内容，可重试」 |

| 测试无结果 | 展示空状态 | 「当前配置下未召回任何结果」 |
| 发布时对象已删除 | 阻止该条发布 | 「该问答对已被删除，无法发布」 |
| 发布时并发冲突 | 拒绝该条并列出差异 | 「该对象已被他人修改，请确认后重试」 |
| 发布部分失败 | 全部回滚 | 「发布失败，已回滚，线上未受影响」 |
| 网络中断 | 保留本地草稿，提示重试 | 「网络异常，变更未保存，请重试」 |
| 权限不足 | 阻止操作 | 「无权限执行该操作」 |
| 会话过期 | 跳转登录 | 「登录已过期，请重新登录」 |

## 十二、上线计划、依赖与上线后验证

### 12.1 分期

| 阶段 | 内容 | 预估 | 验收标准 |
|---|---|---|---|
| P0 修通链路 | ① `UpdateChunk` 重算 `question_tks` / `important_tks`（ES 必需；Infinity 需实测确认）；② 检索结果返回 `question_kwd`；③ 同义词页面注册路由 | 2~3 天 | 改相似问后检索能测出变化；检索结果能看到命中的相似问 |
| P1 词表与相似问管理 | 词表管理页、专有词表、相似问管理页、手工编辑、批量导入 | 1.5~2 周 | 运营可独立完成一次词表与相似问维护 |
| P2 变更暂存 | 待生效区、变更中心、撤销/放弃 | 3~5 天 | 编辑不影响线上，变更可撤销 |
| P3 测试对比 | 测试弹窗、原/新对比、查询扩展对比、差异摘要 | 1~1.5 周 | 发布前可看到两套配置的问答差异 |
| P4 智能生成 | 批量生成、进度、候选勾选、去重 | 1~1.5 周 | 1000 问答对可断点续跑，采纳率可观测 |
| P5 发布与审计 | 发布校验、原子发布、发布记录、审计 | 3~5 天 | 发布可追溯，失败可回滚 |

### 12.2 依赖就绪度评估

| 依赖项 | 所属系统 | 就绪状态 | 分级 | 最晚就绪时限 | 影响与替代方案 |
|---|---|---|---|---|---|
| `UpdateChunk` 重算 `question_tks` | RagFlow Go 后端 | 未改造 | **阻塞** | P0 结束前 | 不修则改相似问在 ES 上完全无效，测试对比失去意义；替代方案：改用 Infinity 引擎（当前生产为 Infinity） |
| 检索结果返回 `question_kwd` | RagFlow Go 后端 | 未改造 | **阻塞** | P0 结束前 | 不修则无法做命中归因；替代方案：无，必须改 |
| 同义词前端路由 | RagFlow 前端 | 未注册 | **阻塞** | P1 开始前 | 页面已存在，加路由即可 |
| QA 流水线支持 Extractor 或新增批量生成接口 | RagFlow Go 后端 | 未实现 | **阻塞** | P4 开始前 | 不实现则只能手工维护相似问 |
| 租户 LLM 模型与配额 | RagFlow 模型服务 | 已就绪 | 并行 | P4 联调前 | 模型不可用时降级为手工编辑 |
| ES/Infinity 测试索引能力 | 检索引擎 | 已就绪 | 并行 | P3 联调前 | 沙箱构建失败时降级为候选重排 |
| 华夏基金产品与术语清单 | 甲方 | 待提供 | 并行 | P1 上线前 | 清单缺失则专有词表效果有限，需在合同中明确由甲方提供 |

### 12.3 上线后验证

| 验证项 | 方法 | 通过标准 |
|---|---|---|
| 相似问修改可测出效果 | 在测试环境改一条相似问，跑测试对比 | 新配置下对应 query 的分数或排名发生变化 |
| 词表修改即时生效 | 新增同义词后发布，用别名检索 | 能召回标准词对应问答对 |
| 编辑不影响线上 | 保存待生效变更后，用线上检索验证 | 结果与修改前一致 |
| 发布原子性 | 构造一条冲突变更，执行发布 | 全部回滚，线上无部分生效 |
| 批量生成可用 | 对 100 个问答对执行生成 | 任务完成率 ≥95%，可断点续跑 |
| 审计可追溯 | 查询变更历史 | 能定位到操作人、时间、前后值 |

## 十三、风险与遗留问题

### 13.1 风险登记册

| 编号 | 风险描述 | 类别 | 概率 | 影响 | 等级 | 应对措施 | 责任人 | 状态 |
|---|---|---|---|---|---|---|---|---|
| RK-01 | `UpdateChunk` 不重算 `question_tks`，ES 上改相似问无效；Infinity 需实测确认 `questions` 列是否同步 | 技术 | 5 | 5 | 25 高 | P0 必修；分别在 ES 与 Infinity 上验证「改相似问 → 检索分数变化」 | 后端 | 待处理 |
| RK-02 | 检索结果不返回 `question_kwd`，无法做命中归因 | 技术 | 5 | 4 | 20 高 | P0 修 `retrieval.go` 的 `src` 与 `resultChunk` | 后端 | 待处理 |
| RK-03 | 测试沙箱构建成本随受影响 chunk 数上升 | 性能 | 3 | 4 | 12 中 | 限制单次测试 ≤50 chunk；超出转异步；失败降级候选重排 | 后端 | 待处理 |
| RK-04 | 多 KB 检索只应用第一个 KB 的同义词，测试可能串味 | 技术 | 3 | 4 | 12 中 | 测试时强制单 KB；发布时按 KB 分别校验 | 后端 | 待处理 |
| RK-05 | 甲方无法提供基金产品与术语清单，专有词表效果有限 | 需求 | 4 | 3 | 12 中 | 合同明确甲方提供；先内置一批通用基金术语兜底 | 产品 | 待确认 |
| RK-06 | 生成内容引入答案中不存在的事实，造成合规风险 | 合规 | 3 | 5 | 15 高 | 生成结果必须人工勾选；敏感词过滤；提示词约束「不得引入答案外信息」 | 算法 | 待处理 |
| RK-07 | 并发编辑导致发布覆盖他人改动 | 数据 | 3 | 4 | 12 中 | 发布前逐条比对变更前值，冲突条目拒绝合并 | 后端 | 待处理 |
| RK-08 | 变更暂存与现有分块编辑（直接改 `question_kwd`）并存，产生双写 | 数据 | 4 | 3 | 12 中 | 分块编辑弹窗改为写 `chunk_question` 待生效表；保留兼容读取 | 前端+后端 | 待处理 |
| RK-09 | 相似问数量膨胀导致检索性能下降 | 性能 | 2 | 3 | 6 低 | 单条问答对建议 ≤20 条；超限提示；监控检索耗时 | 后端 | 观察 |
| RK-10 | 测试结果与发布后实际效果不一致 | 体验 | 2 | 4 | 8 中 | 沙箱与发布使用同一套 token 计算逻辑；发布后抽样复测 | 后端 | 待处理 |

### 13.2 待确认事项

1. **寒暄库的解析类型**：是否与 FAQ 库同为 `qa`？若不同，词表与相似问能力需单独适配。
2. **作用域优先级**：知识库级词表与租户全局词表同时命中时，是「知识库覆盖全局」还是「两者合并」？本 PRD 暂定前者。
3. **测试沙箱的 chunk 上限**：单次测试最多支持多少个受影响 chunk？本 PRD 暂定 50，超出转异步。
4. **发布审批**：是否需要客服主管审批后才可发布？本 PRD 暂定运营可直接发布。
5. **生成模型的成本归属**：批量生成消耗的 token 是否计入租户配额？本 PRD 暂定计入。
6. **相似问上限**：单条问答对相似问数量上限是多少？本 PRD 暂定建议 20、不硬性阻断。
