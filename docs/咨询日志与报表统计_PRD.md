## 一、背景与目标

### 1.1 背景

华夏基金智能客服每天产生大量客户对话，但当前只有「运行日志」（技术视角的 run 记录），
没有「客户服务视角」的数据分析能力：

- 客服主管看不到「今天有多少客户咨询、问了什么、答得好不好」
- 运营看不到「响应慢不慢、哪些问题答得差、客户满意不满意」
- 合规需要追溯「某个客户某天说了什么」

对话数据其实都存在了（`conversation` / `conversation_message`），缺的是**一层面向业务的分析视图**。

### 1.2 目标

| 目标 | 说明 |
|---|---|
| 可查明细 | 按客户、时间、应用、评价维度检索每轮对话明细 |
| 可看统计 | 咨询量、客户数、响应速度、准确率等指标一目了然，支持趋势与维度下钻 |
| 可追溯 | 从统计数字下钻到具体对话明细，支撑合规与质检复盘 |

### 1.3 成功指标

| 指标 | 目标 |
|---|---|
| 咨询日志可检索覆盖率 | 100%（所有会话均可按客户 id 检索） |
| 报表数据延迟 | T+1 内可查（实时为增强） |
| 响应速度数据完整率 | 链路 2 100%；链路 1 补埋点后 ≥99% |

## 二、名词与指标口径（评审重点）

> 指标口径是本 PRD 的灵魂。以下每个口径都定义了「怎么算、排除什么、单位」，评审时逐条确认。

| 指标 | 口径定义 | 单位 | 数据源 |
|---|---|---|---|
| **咨询量** | 统计周期内的对话会话数（`conversation` 去重）。一个客户多次咨询 = 多个会话 | 次 | `conversation` |
| **咨询客户数** | 统计周期内去重客户数（`user_id` 去重） | 人 | `conversation.user_id` |
| **平均对话轮次** | 总会话内问答轮次 ÷ 会话数 | 轮/会话 | `conversation_message` |
| **响应速度** | 平均首包延迟：用户消息发出 → 首个回答 delta 返回 | 秒 | 链路 2 用 `agent_run.duration_ms`（MVP 总耗时代理）；链路 1 需补埋点（见 §5.2） |
| **准确率（代理）** | 双口径：**好评率** = 好评数 ÷ 有评价的回答数；**成功率** = 成功会话 ÷ 总会话 | % | `thumb_up` / `agent_run.status` |
| **评价分布** | 好评 / 差评 / 未评价 占比 | % | `thumb_up` |
| **token 消耗** | 周期内 Prompt + Completion token 合计 | 个 | `agent_run` |

**关键澄清**：

1. **「准确率」是代理指标，不是语义准确率。** 严格准确率需要人工对回答逐条标注
   （正确 / 部分正确 / 错误），本版用「好评率 + 成功率」近似，V2 引入人工标注。
   界面必须标注「好评率（近似准确率）」，不误导。

2. **「响应速度」在两条链路口径不一致（MVP 阶段）**：
   - 链路 2（对话流/工作流）有 `duration_ms`（总耗时，含推理）
   - 链路 1（聊天）当前无耗时埋点，需补首包延迟
   - MVP 明确标注每条数据的时间口径，混算前先对齐（见 §5.2）

3. **「客户 id」的口径待确认**（见 §8 待确认 Q1）：
   现有 `user_id` 是登录用户 id 还是匿名访客 id，决定「咨询客户数」是否准确。

## 三、需求范围

### 3.1 本期包含（V1.0）

| 模块 | 内容 |
|---|---|
| 咨询日志 | 会话维度明细列表、按客户/应用/时间/评价筛选、详情抽屉（完整对话流 + 评价 + 耗时 + 引用） |
| 报表统计 | 指标卡（咨询量/客户数/响应速度/准确率/轮次/token）、趋势图、按应用维度拆分、下钻到明细 |
| 数据补全 | 链路 1 聊天补响应速度埋点（首包延迟） |

### 3.2 本期不包含

| 能力 | 计划版本 | 原因 |

| 转人工率、情绪分析 | V2.0 | 依赖质检/转人工数据沉淀 |
| 实时大屏 | V2.0 | 先做 T+1 报表，验证需求 |
| 自定义报表（拖拽式） | V2.0 | 先用固定指标 |
| 跨应用聚合看板 | V1.1 | V1.0 先按应用看，再做全局 |

## 四、现有数据基础盘点（可行性结论）

| 数据 | 现状 | 位置 |
|---|---|---|
| 会话 | ✅ | `conversation`（ChatSession），含 `user_id`、`dialog_id` |
| 消息 | ✅ | `conversation_message`（ConversationMessage），含 `role`、`content`、`thumb_up`、`feedback`、`created_at` |
| 引用 | ✅ | `conversation_reference`，含相似度等 |
| 评价 UI | ✅ 已实现 | `feedback-dialog.tsx`、`group-button.tsx`（点赞/点踩/反馈） |
| 运行耗时 | ⚠️ 仅链路 2 | `agent_run.duration_ms`、`status`、`prompt_tokens`、`completion_tokens`、`trigger_type` |
| 聊天耗时 | ❌ 无 | 链路 1 消息表无耗时字段 |
| 聚合报表 | ❌ 无 | 需新写聚合查询 + 前端图表 |

**结论：这是「数据已在、补一块埋点、建一层分析」的需求，不是从零采集。** 工作量集中在报表层与链路 1 埋点。

## 五、功能需求

### FR-01 咨询日志

| 编号 | 需求 | 业务规则 | 验收标准 |
|---|---|---|---|
| FR-01-01 | 会话明细列表 | 以会话为行，列：客户 id、应用、咨询时间、轮次、评价、耗时、首问摘要 | Given 进入咨询日志，Then 按时间倒序展示会话列表 |
| FR-01-02 | 多条件筛选 | 时间范围（必选，默认近 7 天）、应用、评价（好/差/未评）、客户 id、关键词 | Given 选应用+差评，Then 只显示该应用差评会话 |
| FR-01-03 | 关键词检索 | 检索咨询内容与回答内容全文 | Given 搜「赎回」，Then 命中含「赎回」的会话 |
| FR-01-04 | 详情抽屉 | 展开某会话，显示完整对话流（每轮：客户问 → AI 答 → 评价 → 耗时），答附引用 | Given 打开详情，Then 按时间顺序展示每轮问答 |
| FR-01-05 | 评价展示 | 每条 AI 回答显示 👍/👎/未评价；有文字反馈时展示 | Given 有反馈，Then 显示反馈原文 |
| FR-01-06 | 分页与导出 | 分页（默认 20/页）；导出 CSV 按当前筛选 | Given 导出，Then CSV 行数与筛选结果一致 |
| FR-01-07 | 权限 | 按租户隔离；仅管理员/质检员可见 | Given 跨租户访问，Then 404 |

### FR-02 报表统计

| 编号 | 需求 | 业务规则 | 验收标准 |
|---|---|---|---|
| FR-02-01 | 指标卡 | 咨询量、咨询客户数、响应速度、好评率、成功率、平均轮次、token 消耗；每卡含环比 | Given 进入报表，Then 顶部展示指标卡 |
| FR-02-02 | 时间范围切换 | 今天 / 近 7 天 / 近 30 天 / 自定义 | Given 切近 7 天，Then 所有指标按 7 天重算 |
| FR-02-03 | 趋势图 | 咨询量与好评率按日趋势（折线/柱状） | Given 选近 30 天，Then 显示 30 天趋势 |
| FR-02-04 | 应用维度 | 按应用拆分的指标表（应用名、咨询量、客户数、响应、好评率） | Given 看应用维度，Then 每个应用一行 |
| FR-02-05 | 下钻 | 点击指标卡或应用行，跳转到带筛选条件的咨询日志 | Given 点「差评 20」，Then 打开差评的咨询日志 |
| FR-02-06 | 口径说明 | 每个指标悬停显示口径定义（见 §2） | Given 悬停响应速度，Then 显示口径 |

### FR-03 链路 1 响应速度埋点

| 编号 | 需求 | 业务规则 | 验收标准 |
|---|---|---|---|
| FR-03-01 | 首包延迟记录 | 聊天应用记录「用户消息到达 → 首个回答 delta」的延迟，写消息级字段 | Given 发起对话，Then 消息记录含耗时 |
| FR-03-02 | 存量兼容 | 存量消息无耗时，报表标注「—」不参与均值 | Given 查历史，Then 无耗时消息不计入响应速度 |

## 六、数据与埋点

### 6.1 数据模型变更

**复用**：`conversation`、`conversation_message`、`agent_run`、`conversation_reference`。

**新增 1 字段**（链路 1 埋点）：

```sql
ALTER TABLE conversation_message ADD COLUMN duration_ms INT NOT NULL DEFAULT 0;
```

`duration_ms` = 首包延迟毫秒，仅 role=assistant 的消息有意义；0 表示未记录（存量/异常）。

### 6.2 埋点

| 事件 | 时机 | 字段 |
|---|---|---|
| 无新增埋点 | 响应速度复用消息表 duration_ms | — |

> 数据采集已在现有链路完成，本功能主要是「读」现有数据 + 补一个耗时字段，不新增埋点事件。

## 七、异常与边界

| 场景 | 处理 |
|---|---|
| 客户 id 为空（匿名访客未生成 id） | 显示「匿名访客」，不参与「咨询客户数」去重（或按会话 id 兜底，待确认 Q1） |
| 无耗时消息（存量/链路 1 未埋点） | 响应速度统计跳过，标注「—」 |
| 无评价的消息 | 计入「未评价」，不计入好评率分母 |
| 时间范围过大（>90 天） | 提示缩小范围，避免全表扫 |
| 导出数据量超限 | 限制单次导出 ≤10 万行，超出提示分批 |
| 会话跨应用 | 会话归属以 `dialog_id` / `canvas_id` 为准 |

## 八、风险与待确认

### 8.1 风险

| 编号 | 风险 | 概率 | 影响 | 等级 | 应对 |
|---|---|---|---|---|---|
| RK-01 | 「准确率」口径误导客户 | 4 | 4 | 16 高 | 界面明示「好评率（近似准确率）」；V2 引入人工标注 |
| RK-02 | 链路 1 与链路 2 响应速度口径不一致 | 4 | 3 | 12 中 | MVP 分链路标注口径；对齐后再混算 |
| RK-03 | 大表查询拖慢库 | 3 | 3 | 9 中 | 时间范围必选；加索引；聚合走异步/预计算 |
| RK-04 | 客户 id 语义不清导致客户数失真 | 3 | 3 | 9 中 | 待确认 Q1，确认后统一 |

### 8.2 待确认

| # | 问题 | 影响 |
|---|---|---|
| Q1 | `user_id` 是登录用户还是匿名访客？智能客服大多是匿名访客，需确认访客 id 生成方式 | 决定「咨询客户数」口径 |
| Q2 | 响应速度用「首包延迟」还是「完整响应时间」？ | 决定埋点与口径 |
| Q3 | 报表是「实时」还是「T+1」？ | 决定架构（实时聚合 vs 预计算） |
| Q4 | 是否需要「准确率」严格口径（人工标注）？ | 决定是否规划 V2 标注功能 |
| Q5 | 咨询日志是否需要区分「链路 1 聊天」与「链路 2 对话流」？ | 决定列表维度 |
