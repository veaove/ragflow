|---|---|---|
| F 文档全生命周期 | 12 | 上传 → 解析 → **chunk 产出** → **召回内容含原文** → 删文档 → **chunk 归零** |

## 发现的问题

### 1. `GET /qc/rules/selection` 返回的不是真实生效集（设计风险）

实测 `db888754`：

| 视角 | 结果 |
|---|---|
| `qc_rule.app_id` 归属 | 2 条规则 |
| `GET /qc/rules/selection` | 返回这些规则（界面显示「已选用」）|
| **`qc_rule_binding`（真实生效）** | **0 条** |
| 实际拦截行为 | **不拦截** |

**用户在「选用规则」页看到规则是选中的，但它并不生效。**
这是配置界面与运行时判定之间的语义断层，建议产品侧确认：
要么 `GET` 改为直接读 binding，要么在无绑定时给出明确提示。

### 2. 测试自身污染了生产配置（已恢复）

`PUT /qc/rules/selection` 是**全量替换**。我按 `GET` 的返回值做替换，
误把 5 条生产规则（国家政策、世界大势等）绑到了该应用。

已用 SQL 恢复：binding 归零、总数回到 9。

**脚本已加固**：先查 `qc_rule_binding` 计数，**非 0 直接 SKIP**，
不碰生产在用的应用；恢复也用 SQL 精确清空，不依赖 PUT 语义。

### 3. 用例自身的假阳性（已修）

`Q='\"...\"'` 在单引号里是字面反斜杠 → JSON 非法 → 回答为空，
导致「不等于拦截提示」的断言被空字符串骗过。改成 `Q='"..."'` 后才真正有效。
