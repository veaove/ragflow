## 二、环境能否真跑（测试前置结论）

很多项目在无模型环境下只能测参数校验，这份报告先回答"能不能真跑"：

| 能力 | 配置 | 结论 |
|---|---|---|
| chat | `qwen-flash` / `deepseek-v4-pro`（model_type=1, active） | ✅ 可对话 |
| embedding | `text-embedding-v3` / `text-embedding-v4`（type=2） | ✅ 可向量化 |
| rerank | `qwen3-rerank`（type=16） | ✅ 可重排 |

实证：
- 检索 `POST /datasets/:id/search` 返回真实 chunk（相似度、内容齐全）
- 智能体 `POST /agents/:id/run` 返回 SSE 事件流（`workflow_started` → `node_started`）

**所以业务测试没有降级成"只测 4xx"，检索真的召回了、智能体真的跑了。**

## 四、三轮失败全部是用例问题，不是产品缺陷

首轮 52/55，三条失败逐一定性：

| 用例 | 现象 | 定性 |
|---|---|---|
| A9 标签聚合 | code=102 `Lack of dataset_ids` | **接口要求显式传参**，用例漏了 |
| C14 无 error 事件 | 断言失败 | **断言写反**：用 `ckn`（不等于 0）断言"应为 0" |
| D7 更新规则 | code=101 `at least one keyword is required` | **PUT 是全量替换语义**，只传 name 不合法 |

修正后 55/55。**没有一条是产品 bug。**

这与上一轮形成对比——上轮权限测试抓到了 2 个真缺陷（成员列表 role 恒空、移除成员后部门删不掉）。
业务功能的实现质量明显更稳，问题集中在**接口契约的细节**（必填参数、全量替换语义）上。
