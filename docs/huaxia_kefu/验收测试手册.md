## 二、逐项详解

### 1. FAQ 知识管理

**从哪进**：左侧「知识库」→ 点卡片「**华夏基金FAQ话术**」→ 左侧子菜单「**文件**」
直链：`http://172.30.20.51/dataset/files/ab87ed24c99f4dec92281414532f3bb1`

**关联了什么**
- 库 `ab87ed24c99f4dec92281414532f3bb1`：qa 形态 / Chinese / **119 chunk** / 源文件 `faq库.xlsx`
- 沙箱库 `28b6b9ded3da4510a1b1b74565886907`：同源 119 chunk 副本（第 7 项用）
- 被三个出口引用：华小夏-客服（第 1 位）、华小夏-沙箱（改用沙箱库）、华小夏-IVR（默认分支检索）

**怎么设计的**
- **一个标准问 = 一个 chunk**（qa 形态）：问题进 `question_kwd`，答案进 `content`，检索命中直接拿原文，不做二次改写 —— 客服要的是原话，不是模型复述。
- **问题与答案分离**：相似问只改"问法侧"，永远不动答案，所以扩召回不会改口径。
- **分渠道不靠给 chunk 打标签，靠"应用绑哪个库"**：生产客服绑 3 库、沙箱绑沙箱库、IVR 走固定答 + 3 库兜底。
  理由：199 个 chunk 逐条打 `channel` 标签不可维护，而当前渠道间唯一真实差异是「电话侧念不了长文」，用应用就能表达。
- **蓝凌同步**：不做对接，只对外承诺（接口能力真实存在：文档上传 / 更新 / 状态查询）。这是评审拍板的范围。

**进去怎么操作**

| 步 | 操作 | 看到什么 |
|---|---|---|
| 1 | 进「文件」，看列表 | 1 个文件、状态「已解析」、chunk 数 119 |
| 2 | 点文件名进详情 | 解析出的问答对逐条列出；随便点一条能看到「问题 / 答案」结构 |
| 3 | 右上「新增文件」传一个小 txt 或 xlsx | 状态经历 未解析 → 解析中 → 已解析，chunk 数增加 |
| 4 | 列表行右侧「…」→ 停用 / 启用 | 停用后该文档不再参与检索（注意：**启停是 `is_enabled`，不是 `status`**） |
| 5 | 左侧「配置」 | 看 language=Chinese、embedding 模型、解析方法（这些是硬前提，别乱改） |

**判定通过**：能看到 119 chunk、能新增并解析成功、能停用一条且检索里不再出现。

**边界**：`language` 必须 Chinese —— 设成 English 会让 `content_ltks` 分不出中文词，关键词检索整条失效（本库是对的）。平台没有文档下载 API，取原文要走对象存储。

### 2. 相似问 / 同义词等配置

**从哪进**：知识库 → 华夏基金FAQ话术 → 左侧「**相似问管理**」/「**词表管理**」
直链：`/dataset/similar-question/ab87ed24c99f4dec92281414532f3bb1`、`/dataset/vocab/ab87ed24c99f4dec92281414532f3bb1`

**关联了什么**
- **15 个标准问挂了 82 条相似问**（例：「华夏基金是什么时候成立的」挂 5 条：哪年成立的 / 几年了 / 成立多久…）
- **13 组同义词**：FAQ 库 10 组（申购 / 认购 / 赎回 / 定投 / 净值 / 分红 / 客服电话 / 风险测评 / 网上交易 / 华夏成长混合）+ 服务渠道库 3 组（服务渠道 / 开户银行 / 线下网点）
- 别名示例：「华夏成长混合」挂 `华夏成长 / 华夏成长基金 / 华夏成长证券投资基金 / 000001`

**怎么设计的**
- 相似问落 `question_kwd`，和原问题一起参与关键词与向量两路召回；**一问多写，不改答案**。
- 同义词是**查询期展开**（词典只在检索时生效），不是入库时改字 —— 所以配错能立刻回滚，不用重解析。
- **改动是分层的**：在界面上改相似问 / 同义词，先进「变更中心」的待生效区，
  **发布后才影响线上检索**（发布时自动失效词典缓存，不用重启）。这样批量改错了能整批放弃。
- 「scope」字段是装饰：检索侧只按 `dataset_id` 取词典，跨库想生效只能**每个库各建一套**（我们就是这么做的）。
- 录入纪律：每条 6–30 字、模拟客户口语、单个标准问 5–15 条；超过反而稀释权重。

**进去怎么操作**

| 步 | 操作 | 看到什么 |
|---|---|---|
| 1 | 相似问管理 → 搜「华夏基金是什么时候成立的」 | 该标准问下挂 5 条相似问 |
| 2 | 点「新增相似问」，加一条「成立多久了」，提交 | 提示已进入变更集（**此时还没生效**） |
| 3 | 左侧「变更中心」 | 待生效区里能看到这条改动，「测试对比 / 选中发布 / 放弃选中」 |
| 4 | 点「选中发布」 | 发布成功，相似问管理里可见 |
| 5 | 回知识问答 → 华小夏-客服，问「成立多久了」 | 命中该条（发布后才生效，第 4 步之前问是命中不了的） |
| 6 | 词表管理 → 看 10 组 | 点开「华夏成长混合」，5 个别名含 000001 |
| 7 | 问「你们的服务电话是多少」 | 命中客服电话（同义词把"服务电话"展开成"客服电话"） |

**判定通过**：15 个标准问可查、82 条可数、任意两条口语问法能召回。
**边界**：① 相似问不是"另一个问题的答案"，别把不同业务的问题挂到同一条标准问下；② 同义词组不能跨库复用；③ 忘了去变更中心发布，等于没改。

### 3. 寒暄知识库

**从哪进**：知识库 → 卡片「**华夏基金寒暄库**」
直链：`/dataset/files/01eea2cd12e1438ca7a06ef1031baeb0`
看口语变体：同一页 → 左侧「**相似问管理**」，直链 `/dataset/similar-question/01eea2cd12e1438ca7a06ef1031baeb0`

**关联了什么**
- 库 `01eea2cd12e1438ca7a06ef1031baeb0`（qa / **12 chunk = 12 个寒暄意图**），每个意图带 2~14 条相似问。
- **三个入口都绑了它**：华小夏-客服（问答应用）、夏管家推送（智能体）、华小夏-IVR（按键菜单）。
- 同义词组 1 套：「寒暄问候」9 词（你好/您好/在吗/在么/在不在/有人吗/hi/hello/哈喽）。**同义词组按库生效，不跨库**，所以这套只服务寒暄库。

**怎么设计的**
- **独立成库，不混进 FAQ**。混库时寒暄答案会抢业务问题的 top_n（实测问「在吗」答出一段业务条款）。
  单独成库后，它只在"真的是寒暄"时才进 prompt。
- **一个意图一个 chunk，不把十组问答塞进一段**。这是本项返工过一次的地方：原来整份 txt 只切出 2 个 chunk，
  里面挤了 10 组问答，向量是 10 个意图的平均值 —— 实测「有人吗」只能得 0.2 分，
  且 chunk 的 `question_kwd` 为空，关键词检索这一路直接 0 分，最后表现为"换个说法就兜底"。
- **一段文本混多个意图 = 检索必然失效**，这是通用规律，不止寒暄：chunk 是检索的最小单位，
  一个 chunk 只能表达一个语义。
- **口语变体走"相似问"而不是只靠同义词**：相似问落进 chunk 的 `question_kwd`，参与关键词加权匹配；
  同义词只在查询期展开。两个都要，前者管"这个库认不认"，后者管"查询能不能被改写"。

**进去怎么操作**

| 步 | 操作 | 看到什么 |
|---|---|---|
| 1 | 知识库 → 华夏基金寒暄库 → 文件 | 1 个文档 `华夏基金-寒暄知识库.txt`，12 个 chunk |
| 2 | 点任一条 chunk | 正文是「问题：你好 回答：您好，我是华夏基金智能客服小夏…」 |
| 3 | 左侧「相似问管理」 | 能看到「你好」下挂着 14 条口语变体（有人吗、hello、在不在…） |
| 4 | 知识检索测试 → 问「有人吗」 | 命中「你好」那条，分数约 0.32 |
| 5 | 知识问答 → 华小夏-客服 → 问「有人吗」 | 答「您好，我是华夏基金智能客服小夏…」 |
| 6 | 智能体 → 夏管家推送 → 对话 → 问「有人吗」 | 同一句寒暄，不串业务条款 |
| 7 | 智能体 → 华小夏-IVR → 对话 → 问「hello」 | 同一句寒暄 + 「回复0回到菜单」 |

**判定通过**：`有人吗` / `hello` / `在吗` / `谢谢` / `你是谁` 五个问法在**三个入口**都答寒暄；
同时问 `基金定投的起点金额是多少`、`你们支持哪些银行卡` 仍然答业务，不被寒暄挤掉。

**边界**
- **别把多个意图塞回一个 chunk**：一行一对，全角逗号「，」；半角逗号是问题/回答的分隔符，
  多打一个就会把两个意图粘成一条（`scripts/huaxia_configure.py greet` 会先校验再上传）。
- **同一个口语变体只能挂一个意图**：挂两处会让两个 chunk 得分打平，排序随机。
- **阈值 0.28 是实测出来的**，不是拍的：改它之前先跑 `python scripts/huaxia_configure.py probe`。
  依据和三个反例都写在脚本 `RETRIEVAL_TUNING` 上面。
- 「谢谢 / 再见 / 早上好」这类不是同义关系，**不要合并进「寒暄问候」同义词组**，
  否则问「谢谢」会召回「在吗」的答案。它们各自成 chunk 就够了。

### 4. 用户咨询日志及报表统计

**从哪进**
- 主入口：左侧「**总览**」（`/overview`，报表面板嵌在页内）
- 独立页：`/analytics/stats`（统计）、`/analytics/consultations`（会话明细）

**关联了什么**：4 个接口 —— `/analytics/stats`、`/analytics/stats/apps`（按应用分列）、`/analytics/consultations`（明细）、`/analytics/stats/trend`（趋势）。

**怎么设计的**
- 日志是**运行时自然落库**（会话 + 消息表），报表只做只读聚合，不改业务表。
- 客户评价用消息上的点赞/点踩（知识问答里有；智能体运行面板显式关掉了，避免误点）。
- 按应用分列是考核的关键维度：沙箱、IVR 的会话会混在同一张表里，得靠 `app_id` 分。

**进去怎么操作**

| 步 | 操作 | 看到什么 |
|---|---|---|
| 1 | 先在 华小夏-客服 里问 2 句 | 正常回答 |
| 2 | 回「总览」刷新 | 咨询量 +2、客户数、平均轮次 |
| 3 | 看「按应用统计」 | 华小夏-客服 一行的量增加 |
| 4 | 进 `/analytics/consultations` | 刚才那个 session 在明细里，能看开始时间、轮次 |
| 5 | 看趋势图 | 按天分布 |

**判定通过**：有量、有按应用分布、明细能对上刚才的时间点。

**缺口（必须说清）**：**响应速度 `response_ms` 恒为 null** —— 目前没有埋点，"响应速度"这个指标查不到；「准确率」没有标注数据，不做。需求 4 若要考核这两项，属开发项。

### 5. 【定制】夏管家推广管理

**从哪进**：左侧「智能体」→ 列表里「**夏管家推送**」
直链：`http://172.30.20.51/agents/8e19bc6c18eb42e093bd6bd7ae433e5b`

**关联了什么**
- 拓扑：`Begin → Switch(命中"人工") → Message(推二维码)` ／ `Switch 默认 → 改写 → 检索 → 生成`
- 检索节点绑 **2 库：FAQ话术 + 寒暄库**（原来只有 FAQ，客套话问「在吗」只能答成业务条款）
- 二维码在 `Message:FamousBananasWalk` 的 content 里，**目前仍是占位符 `xxxx`**
- 开关状态：`release=false`（未上架）

**怎么设计的**
- **转人工不用模型判断，用 Switch 关键词**（contains 人工 / 转接）：稳定、可预测、零延迟。
  要加触发词就在 Switch 里加一条 `contains`；要改引导语/二维码就改对应 `Message` 节点的内容，都只动一处。
- **配置开关就是"上架/下架"**。原因是 Begin 组件的 inputs 在 conversational 模式会被用户输入覆盖
  （实测 `begin.outputs` 里就是用户原话），塞不进一个配置项到 Switch 里判断；用发布开关最干净，关掉入口就消失。
- **检索参数与另外两个入口用同一套**（`RETRIEVAL_TUNING`：rerank 开 / thr 0.28 / 关键词权重 0.37）。
  这条是踩过坑才统一的：原来夏管家是 thr 0.2 + 关键词权重 0.7 + 关 rerank，
  同一句「有人吗」在客服能答、在夏管家得 0.15 分答不出，客户会当成 bug。
- 二维码单独放一个 Message 节点，换素材只改一处。

**进去怎么操作**

| 步 | 操作 | 看到什么 |
|---|---|---|
| 1 | 打开「夏管家推送」→ 右上「运行」 | 右侧聊天面板 |
| 2 | 说「我要人工」 | 推二维码消息（现在显示的是占位图/破图，属预期） |
| 3 | 说「基金定投的起点金额是多少」 | 正常检索作答（证明不是只会推码） |
| 4 | 说「有人吗」 | 寒暄话术（证明寒暄库真的绑上了，不只是 FAQ） |
| 5 | 画布上看 Switch 的两个出边 | 一条到 Message，一条 `end_cpn_ids` 到改写 |

**判定通过**：两条分支都正确。
**缺口**：二维码占位、未上架。客户给真图后：改 `Message:FamousBananasWalk` → 跑 `huaxia_configure.py transfer --publish`（脚本带守卫，还是 `xxxx` 会拒绝上架）。

### 6. AI 效果追踪分析

**从哪进**
- 主入口：智能体 → 打开任一智能体 →「运行」→ 每条回答**上方的「思考过程」折叠块**（默认折叠，点开展开）

**关联了什么**：节点级执行数据来自画布运行时事件（`node_started` / `node_finished`），前端按消息聚合渲染成步骤条。

**怎么设计的**
- 追踪信息本来就随每一次运行产生，不需要额外埋点，**只是默认折叠**：客户视角看答案，排障视角才展开。

- 这次排障（答非所问）就是靠它定位到"改写节点把问题改坏了"，不是检索的问题。

**进去怎么操作**

| 步 | 操作 | 看到什么 |
|---|---|---|
| 1 | 智能体 → 华小夏-IVR（或夏管家推送）→ 运行 | 聊天面板 |
| 2 | 问一句需要检索的话 | 回答上方出现「思考过程」 |
| 3 | 点开折叠块 | 节点顺序 + 每个节点耗时 + 召回条数 + chunk 摘要（可点开看原文） |
| 4 | 打一个数字 `1`（走固定答） | 思考过程里只有 Begin + Switch + Message，**没有检索/生成** —— 证明数字没走模型 |

**判定通过**：能看到节点顺序与耗时；数字分支里没有模型节点。
**边界**：没有独立的"追踪分析报表"页；`/studio` 是隐藏页，不适合教客户自己找。

### 8. 【定制】实时质检管理

**从哪进**：左侧「**会话质检**」→ 顶部 4 个 tab：**质检规则 / 实时质检 / 命中记录 / 系统配置**

**进去怎么操作**

| 步 | 操作 | 看到什么 |
|---|---|---|
| 1 | 「质检规则」tab | 9 条规则，能看到触发维度（用户输入 / AI 回答 / 两者）与动作 |
| 2 | 切「实时质检」tab | 实时校验开关与最近命中 |

**判定通过**：两条都能弹提示，且回答照常给出（没被拦截）。
**边界**：质检是**前端实时校验**，用 API 直接调 `chat/completions` **不会**触发 —— 别用接口测这项。

| 3 | 回对话问一句 | 回答变短/变快（召回变少） |
| 4 | 改回 5 | 恢复基线 |

**判定通过**：7 个关键参数与基线一致，且改动能实时生效。
**缺口**：没有集中管理页，也没有配置变更审计（改了不留痕）。

| 5 | 回知识问答问新问法 | 能召回 |

**判定通过**：能生成、能对比、能发布；发布会前线上检索不变。
**边界**：生成质量依赖模型，必须人工过一遍；生成本身消耗 token，别对全库批量跑；**忘了发布等于没改**。

### 11. IVR 语音配置

**从哪进**
- 平台里：左侧「**智能体**」→「**华小夏-IVR（按键菜单）**」→ 右上「运行」
  直链：`http://172.30.20.51/agents/d84989e4e3ca4d328bfa9a5525418ac9`
- 语音：运行面板**右上角「自动朗读」开关**（打开后开场白与每轮回答自动念；关着就点喇叭）
- 视觉稿：`docs/huaxia_kefu/ivr-demo/index.html`（真按键音的本地模拟器，给客户看电话侧长什么样）

**关联了什么**
- 18 个节点：`Begin(开场白=菜单)` → `Switch` → 10 条固定答（1-9 + 0）/ 默认分支 → `改写 → 检索(3库) → 有无召回 → 生成/兜底`
- 10 条固定答的事实全部来自 FAQ 库原文
- 默认分支绑 3 库：FAQ话术 + 寒暄库 + 服务渠道

**怎么设计的**
- **开场白就是菜单**：Begin 的 prologue，进聊天框第一屏就是「1 客服电话 / 2 定投起点 / … / 0 重听」。
- **数字用 `=` 精确匹配，绝不用 `contains`**：「1998 年成立」里也有 9 和 8，contains 会把正常提问误路由到菜单项。
- **固定答不走模型**：零延迟、零幻觉、零 token；**闲话走检索**：这才是"还能问其他同类问题"。
- **自动朗读**：新一轮开始会掐掉上一轮声音（不叠音），同一句只念一次，切会话不重播历史。
- **话务侧**：平台没有 IVR 引擎（放音收号 / 话务路由 / IVR 报表都没有），真落地由话务平台跑流程、放这 16 段预录音，只在末级那一跳调 RAGFlow 问答。

**进去怎么操作**

| 步 | 操作 | 看到什么 |
|---|---|---|
| 1 | 打开智能体 → 右上「运行」 | 开场白菜单（1~9 + 0） |
| 2 | 打开右上角「自动朗读」 | 菜单被念出来（首次打开页面浏览器可能拦，点一下页面即可补念） |
| 3 | 输入 `1` | 客服热线 400-818-6666 / 010-50919000 + 人工服务时间 |
| 4 | 输入 `3` | 沪深300ETF联接三档费率 0.60%，1000 万以上每笔 1000 元 |
| 5 | 输入 `0` | 菜单重播 |
| 6 | 输入「基金定投的起点金额是多少」 | 100 元起 + 以销售渠道规则为准（**走检索，不是固定答**） |
| 7 | 输入「有人吗」/「hello」 | 寒暄话术 + 「回复0回到菜单」（**同样走检索**） |
| 8 | 点开某条回答的「思考过程」 | 数字分支只有 Begin→Switch→Message；闲话分支有改写→检索→生成 |
| 9 | （可选）本地模拟器：`python -m http.server 8899` → 拨号 → 按 1 → 按 * → 按 9 | 真按键音、按键打断播报、转人工自动挂机 |

**判定通过**：数字固定答准确、0 能回菜单、闲话能检索、自动朗读能出声。
**边界**：① 没有电话线/DTMF，不是可拨号码；② 无 IVR 报表；③ **自动朗读是前端改动，要发版才生效**；④ **别上架** —— 分享页会隐藏喇叭按钮。

## 五、八个容易误判的点

1. **在「智能体」里找华小夏，找不到是正常的** —— 客服/沙箱是「知识问答」里的应用，两个菜单是不同的东西。
2. **相似问命中了但排名不是第一** —— 「客服电话多少」排第 3 属正常，`top_n=5` 都进 prompt，只要目标在这 5 条里就算过。
3. **点喇叭要等约 2 秒** —— 不是坏了，是实时合成；同一段第二次点有缓存，立刻出声。
4. **自动朗读首次打开没声** —— 浏览器拦"无手势自动播放"，点一下页面任意处会补念。
5. **用接口测质检永远不触发** —— 质检走前端实时校验，必须在对话页里说话。
6. **智能体 `release=false` 仍然能试运行** —— release 只管对外发布，不管内部预览。
7. **数字分支的「思考过程」很短** —— 只有 Begin→Switch→Message，说明没走模型，这是设计，不是缺步骤。
8. **沙箱的会话也会进报表** —— 不是数据串了，是同表不同 `app_id`，考核口径要主动排除。

## 七、如果测出问题

按这个顺序自查：

| 现象 | 先看什么 |
|---|---|
| 答非所问 | 知识库 `language` 是不是 Chinese；应用阈值是不是被改高；展开「思考过程」看改写节点 |
| 口语问法召回不到 | 该标准问有没有挂相似问；跑 `eval` 看哪条 FAIL |
| 回答「抱歉，知识库中未找到」 | 阈值太高或 top_n 太小；也可能这条知识库里确实没有 |
| 质检不弹 | 是否在对话页（不是接口）；规则是否被「选用规则」取消掉 |
| 报表没数据 | 看明细页有没有该 session；沙箱应用的记录也会混在里面 |
| 卡片列表里找不到应用 | 是否用 `123456789@qq.com` 登录；应用是 `permission=me`，别人看不到 |
| IVR 打数字没反应 | 是否打成「一」或「１」（全角 0 认，其他全角数字不认）；带空格会走检索 |
| 自动朗读没声 | 开关是否打开；是否还没发版；是否把智能体上架了（分享页无喇叭） |
