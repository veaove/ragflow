## 二、配置场景

**一句话：知识只维护一份，渠道只是出口。**

```
渠道层   WEB/APP 在线客服        IVR 语音           坐席辅助
应用层   华小夏-客服（生产）      华小夏-IVR（播报）   夏管家推送（Agent）
         └ 绑 3 库               └ 绑 2 库（只要短答案）  └ 关键词命中→推二维码
测试层   华小夏-沙箱（模拟测试）  └ 绑 沙箱FAQ + 生产只读库
检索层   同义词归一 → 向量+关键词混合 → qwen3-rerank → 阈值 → top_n
知识层   FAQ话术 | 寒暄 | 服务渠道 || FAQ话术-沙箱
治理层   参数基线 | 质检规则 | 审计 | 报表
```

渠道差异靠**应用绑哪个库**解决，不靠给 chunk 打标 —— 三个渠道当前的真实差异只有一条：
「IVR 不能播报长文本」，所以 IVR 只绑 FAQ 与寒暄两个短答案库。这个用绑定关系就能表达，
不需要为 199 个 chunk 逐个打 `channel` 标签（见 3.4）。

### 3.1 参数基线（已固化到生产应用）

| 参数 | 值 | 为什么是这个值 |
|---|---|---|
| language | Chinese | 硬前置：决定入库分词，设 English 会让关键词检索整条失效 |
| similarity_threshold | 0.35 | 0.2 会放进无关内容（实测召回 13 条清一色不相关） |
| vector_similarity_weight | 0.63 | 关键词 0.37；当前 term_similarity 多为 0，实际生效主要是向量 |
| top_n | 5 | 13 条时 prefill 拖到 18 秒 |
| top_k | 1024 | 召回池，不动 |
| rerank_candidates_count | 104（未动） | v1 建议降到 30，但当前首字已 1.4s，动它收益不确定、风险确定，**维持不动** |
| temperature / top_p | 0.2 / 0.75 | 客服要稳定 |
| frequency/presence_penalty | 0 / 0 | 双开 0.5 会让模型刻意换词 |
| tts | WEB/APP 关，IVR 开 | 按渠道区分 |

**关于「不重建知识库」**：三个库的 `term_similarity` 仍普遍为 0，说明 Infinity 全文索引的
analyzer 在**建表时**就固定了，事后改 `knowledgebase.language` + 重解析回补不了。
但当前向量召回质量足够（实测 vec 0.83～0.97，11/11 用例命中正确 chunk），
而重建的代价是 chunk id 全变、历史引用链接失效、相似问与质检绑定要重做一遍。
**决策：不重建，记为已知限制**，等 P1 做知识分层重构时新建库一次性解决（那时本来就要重建）。

### 3.2 相似问（需求 2，已配 15 个高频标准问 / 82 条）

做法：一个标准问 = 一个 chunk，相似问写进 chunk 的 `questions`，投影到 `question_kwd` 参与检索。
录入纪律：每条 6–30 字、模拟客户口语、单条标准问 5–15 条为宜。

已覆盖：成立时间、客服电话、服务时间、怎么买基金、交易截止时间、确认时间、T+1、
投诉、保本保收益、货币基金是否保本、分红方式、官方 App、购买渠道、风险测评、专户购买。

### 3.3 同义词（需求 2，已配 13 组）

| 库 | 组数 | 内容 |
|---|---|---|
| 华夏基金FAQ话术 | 10 | 华夏成长混合（全称/简称/代码 000001）、申购、认购、赎回、定投、净值、分红、客服电话、风险测评、网上交易 |
| 服务渠道 | 3 | 线下网点、开户银行、服务渠道 |

分类：`fund` = 行业通用词，`hx` = 华夏专属。**纪律**：只放严格同义；
`申购≠认购`（开放期 vs 募集期）、`赎回≠申购`（方向相反）都不合并。
反例不入表：`基金=理财`。

> 实现注意：检索侧词典**只按 dataset_id 加载**（不看 scope 字段），
> 所以跨库生效的唯一办法是每个库各建一套，`scope` 填 `kb` 才与实现一致。

### 3.4 质检规则（需求 8，新增 4 条 + 生产选用 6 条）

| 规则 | 检查对象 | 严重度 | 作用 |
|---|---|---|---|
| QC-收益承诺-提示合规 | 问答双向 | warn | 识别「保证收益/稳赚/包赚」等，提示以基金合同为准 |
| QC-本金安全-提示风险 | AI 回答 | warn | 识别「保本/不亏/零风险」，追加风险提示 |
| QC-投诉-提示转人工 | 用户输入 | warn | 识别「投诉/举报/12386/证监会」，提示转人工 |
| QC-适当性-提示测评 | AI 回答 | warn | 识别「R4/R5/杠杆/私募」，提示风险测评 |

一律 `warn + log_and_alert`（**只提示不拦截**），避免误伤真实咨询。
已通过 `PUT /qc/rules/selection` 把「世界大势」「国家政策」+ 新增 4 条共 6 条绑到生产应用。

> 已有 2 条客户自配规则**保持原样**：`世界大势`（美苏/俄乌/伊朗战争）、`国家政策`（特朗普/希特勒等），
> 都是 `block` 级会拦截回答。**这两条与基金客服场景关系不大且颗粒粗，建议评审是否降级为 warn** —— 未擅自改动。

### 3.5 IVR 播报演示（需求 11）

配置要点（都在应用里，不改代码）：
- `tts=true`、`quote=false`（不念引用标号）
- `top_n=3`、`threshold=0.4`（语音场景宁可说"转人工"也不要答错）
- prompt 强制：纯口语、无 Markdown/列表/表格/括号、**60 字内**、数字按朗读习惯念

实测效果：

| 问题 | 播报文本 | 字数 |
|---|---|---|
| 客服电话是多少 | 客服热线是四零零八幺八六六六六，未开通地区可拨零幺零五零九幺九零零零。 | 35 |
| 基金保本吗 | 基金不保本，购买货币基金不等于存款。详细内容请转人工客服。 | 29 |

数字自动转成中文读法（`400-818-6666` → `四零零八幺八六六六六`），可直接交 TTS。

> **边界要说清**：平台没有 IVR 引擎，做不了按键流程画布、放音收号、话务路由、IVR 报表。
> 本期演示的边界是「ASR 转写 → 调问答 API → 答案 TTS 播报」这一环。
> 正式落地建议话务平台负责流程与放音收号，RAGFlow 作为其中的「智能问答节点」HTTP 接入。

### 3.7 转人工 / 夏管家推广（需求 5）

现状：`夏管家推送` 智能体拓扑为
`begin → Switch(命中"人工") → 推二维码` / `→ 查询改写 → 检索 → 生成回答`，
已实测两条分支都正常（回「我要人工」推二维码；问「基金定投起点金额」走检索并作答，
且带出 `[ID:6d06a13e3f4c9d5f]` 引用）。

**发布状态：保持未上架（`release=false`），这是有意为之，不是遗漏。**
`Message:FamousBananasWalk` 里的二维码地址仍是占位符 `![夏管家客服二维码](xxxx)`，
上架后客户点开是破图。客户提供真实二维码后：

1. 改 `Message:FamousBananasWalk` 的 content，把 `xxxx` 换成真实图片地址；
2. `python scripts/huaxia_configure.py transfer --publish` 上架。

脚本带守卫：二维码还是占位符时 `--publish` 会被拒绝执行，避免误上架。

> 注意 `release=false` 只影响「对外发布」，不影响内部预览与测试 —— 实测未上架状态下
> `POST /agents/{id}/run` 两条分支都能跑，所以流程验证不受阻。

**关于「一键停用转人工」：用平台的发布开关，不改 DSL。** 原因是我实测发现
Begin 组件的 inputs 在 conversational 模式下**会被用户输入覆盖**
（`begin.outputs = {"query":"我要人工","zuoxi_02":"我要人工"}`，配置的 `zuoxi_02=1` 不生效），
没法把开关塞进 Begin 再到 Switch 里判断。停用转人工 = 下架该智能体，入口即消失，零风险。

日常三条纪律：

2. 新增标准问必须带 5–15 条口语化相似问，否则口语问法召不回；
3. 改完跑一次 `eval`，掉到 9/11 以下说明改坏了。
