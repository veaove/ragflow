## 三、易踩坑（复现迁移时必看）

1. **compose 项目名 = 目录名**。容器/卷名前缀 `docker_` 来自 `/root/ragflow/docker` 这个路径，换路径会新建空卷、数据看起来"丢了"。必须保持原路径。
2. **`/usr/share/infinity` 是隐藏依赖**。漏掉时 api 启动即 `Failed to load base analyzer ... fatal`，日志在 `logs/api.log`。
3. **nginx 用 `sites-enabled/default` 会抢占 80**。新机需删除，否则两个 server 块冲突。
4. **`DOC_ENGINE=infinity` 必须显式设置**，否则默认去找 Elasticsearch。
5. **启动服务要指定服务名**：`docker compose up -d mysql minio kvrocks infinity nats`。直接 `up -d` 会带起 `ragflow-cpu` 容器并抢占 80/9380。
6. **ufw 拦不住 docker 发布的端口**：`3306/6379/9000/23817` 在局域网内可直接访问（docker 走 FORWARD 链）。属待加固项。
7. 传输走「新机主动拉旧机」：旧机是公网地址、新机在内网，反向不通。新机 `~/.ssh/migrate_rsa` 的公钥已加入旧机 `authorized_keys`。
