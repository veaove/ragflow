> 每项含操作步骤、预期结果、失败排查方向。建议按 A → B → C → D → E → F 顺序执行，边做边勾。

## B. 部署步骤

### B1. 后端迁移

```bash
cd /root/ragflow
./bin/ragflow_server --migrate
```

**预期**：正常退出，日志无 error。

**必查**：`canvas_template` 是否新增两列

```bash
docker exec docker-mysql-1 mysql -uroot -p$PW rag_flow -N -e "
SELECT COLUMN_NAME, COLUMN_TYPE, COLUMN_DEFAULT
FROM information_schema.COLUMNS
WHERE TABLE_SCHEMA='rag_flow' AND TABLE_NAME='canvas_template'
  AND COLUMN_NAME IN ('lang','base_id');"
```

预期输出两行：

```
lang      varchar(8)   en
base_id   varchar(32)  ''
```

> ❌ 若报 `Unknown column 'lang'` 说明迁移没跑成功，先解决再继续。

### B2. 重启服务（**关键，不能省**）

```bash
systemctl restart ragflow-ingestor ragflow-api ragflow-admin
sleep 5 && systemctl is-active ragflow-ingestor ragflow-api ragflow-admin
```

**为什么必须重启**：模板中文记录由 `SeedCanvasTemplates` 在启动时 upsert 写入。不重启，库里没有中文记录，切中文后列表仍是英文。

### B3. 校验 seed 结果

```bash
docker exec docker-mysql-1 mysql -uroot -p$PW rag_flow -e "
SELECT lang, COUNT(*) AS cnt FROM canvas_template GROUP BY lang;"
```

**预期**：

```
lang  cnt
en    19
zh    15
```

> - `zh` 若为 0 → seed 没跑，查日志 `journalctl -u ragflow-ingestor -n 200 | grep -i "seeded canvas templates"`
> - `zh` 少于 15 → 有中文模板文件解析失败，日志里会有 `Failed to parse agent template`

### B4. 前端构建与切换

```bash
cd /root/ragflow/web
# 按现有流程构建，产物输出到新目录
ls -1d dist_* | tail -3   # 确认新目录已生成
```

切换前**先确认目录存在**，再改 nginx：

```bash
ls -1d /root/ragflow/web/dist_<新时间戳>   # 必须存在
grep -n "root .*/web/dist" /etc/nginx/conf.d/*.conf
nginx -t && kill -HUP $(pgrep -o nginx)
```

**切换后立刻验证静态资源**：

```bash
curl -sI http://127.0.0.1/ | grep -i content-type     # text/html
curl -sI http://127.0.0.1/chunk/js/<某个新 chunk>.js | grep -i content-type  # javascript
```

> ❌ 若 JS 返回 `text/html`，说明 SPA 兜底生效了，静态资源没找到 —— 立刻回滚 nginx root。

## C. 智能体模板中文化（核心，逐项勾）

### C1. 语言切换生效

| 步骤 | 预期 |
|---|---|
| 登录 → 右上角切到**中文** | 界面中文 |
| 进入「智能体」→ 浏览模板列表 | 列表项名称均为中文（如「SEO 博客写手」「深度研究」） |
| 切到**英文** | 列表项变英文（「SEO article writer」「deep research」） |

**判定标准**：中英文切换后，**模板数量一致（19 个）**，不出现同一模板两条。

> ❌ 若中文下出现 38 条（中英各一）→ DAO 的语言去重没生效，检查 `canvas_template.go` 的 `GetAll` 是否被正确调用（传了 `lang`）。

### C2. 提示词可见为中英对应

| 操作 | 预期 |
|---|---|
| 中文环境 → 打开「深度研究」 | 画布节点说明为「你是战略研究总监，在顶级咨询公司有 20 年咨询经验……」 |
| 切英文 → 再打开「深度研究」 | 恢复英文原文 |

**这是最直观的判据**，一眼能看出语言对不对。

### C3. 未翻译模板正常回退

那 4 个纯流程编排模板（`advanced_ingestion_pipeline`、`chunk_summary`、`compiler`、`title_chunker`）没有中文版。

| 操作 | 预期 |
|---|---|
| 中文环境 → 找到这 4 个模板 | **仍出现在列表里**（不消失），名称/描述为中文（走 JSONMap），DSL 内容为英文（无提示词，无感知） |

> ❌ 若这些模板从列表消失 → 回退逻辑写错了，用户会"丢模板"。

### C4. 提示词变量解析（**最关键，必须实测**）

静态校验只能证明花括号没被改动，**不能证明运行时能解析**。必须真跑一次。

| 操作 | 预期 |
|---|---|
| 中文环境 → 克隆「SEO 博客写手」到自己空间 | 创建成功 |
| 在对话框输入：「帮我写一篇关于企业级 RAG 平台的博客，读者是技术负责人」 | 智能体正常逐阶段执行 |
| 观察执行过程 | 各节点之间**有内容传递**（大纲→正文→编辑），不是空白或报错 |
| 最终输出 | 一篇结构完整的博客（有标题、H2 分段、结论） |

**这一项通过，才能证明 `{Agent:xxx@content}` 这类变量没被译坏。**

再抽查两个不同类型的模板：

| 模板 | 输入 | 预期 |
|---|---|---|
| Web 搜索助手 | 「RAGFlow 最新版本有什么变化」 | 有搜索结果 + 引用来源 |
| Text2SQL 专家 | 「列出所有订单」 | 返回一条 SELECT 语句（纯 SQL，无解释文字） |

> Text2SQL 这条特别能验证：如果 SQL 示例被误译、或 `"只输出 SQL"` 的约束失效，模型会输出解释性文字。

### C5. 英文环境回归

| 操作 | 预期 |
|---|---|
| 切到英文 → 克隆「SEO article writer」→ 跑一次同样的对话 | 行为与改造前完全一致，输出英文博客 |

**这是"保障现有功能"的直接证据**——英文用户完全无感。

## E. 私有化模型接入

| # | 操作 | 预期 |
|---|---|---|
| E1 | 中文环境 → 配置中心 → 模型配置 | 左侧「可选模型」底部有「添加自定义模型服务」 |
| E2 | 点击该入口 | 弹窗出现，含：显示名、协议类型、服务地址、API Key、模型清单 |

> E6 是本功能的**安全红线**：云元数据地址必须拦。这条不通过不能上线。

## G. 回滚方案

按影响面从小到大：

| 场景 | 回滚动作 | 耗时 |
|---|---|---|
| 中文模板有问题 | 删除中文记录，无需改代码<br>`DELETE FROM canvas_template WHERE lang='zh';` | 1 分钟 |
| 前端有问题 | nginx root 指回上一个 `dist_*` + `kill -HUP $(pgrep -o nginx)` | 2 分钟 |
| 后端有问题 | 用 `/root/ragflow_backup/` 里的二进制替换 + 重启对应 systemd | 5 分钟 |
| 数据库有问题 | 用 A5 的备份恢复 | 视数据量 |

> **只回滚中文模板不会影响英文用户**——这是双记录方案的设计目的。

## H. 排障对照表

| 现象 | 最可能原因 | 排查入口 |
|---|---|---|
| 切中文后模板列表仍全英文 | ① 服务没重启 ② `lang` 列没建 ③ 前端没传 `lang` | B2 → B1 → Network 面板看 `GET /agents/templates?lang=` |
| 中文下模板重复（38 条） | DAO 语言去重没生效 | `dao/canvas_template.go` 的 `GetAll` |
| 4 个流程模板消失 | 回退逻辑写错 | 同上，检查 `lang == "en"` 分支返回的是否只有 en |
| 智能体运行报变量错误 | 提示词里 `{...}` 被译坏 | 对比 `xxx.json` 与 `xxx.zh.json` 的变量集合 |
| 中文环境下 API 文档仍英文 | 动态 import 失败 / 语言判断没命中 | Network 找 `http_api_reference.zh` chunk；Console 看 import 报错 |
| 自定义模型保存报 driver not found | driver 回退未生效 | `service/model_factory.go` 的 `providerInfo == nil` 分支 |
| 页面空白 / 白屏 | JS chunk 404 被 SPA 兜底 | 看 Content-Type 是否 `text/html` |
