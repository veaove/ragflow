# 对话与问答 - 详细设计

## 1. 模块概述

对话与问答模块是 RAGFlow 的用户交互核心，实现基于检索增强生成（RAG）的问答能力，支持多轮对话、流式输出、引用展示、语音交互与思维导图生成。

## 2. 核心数据模型

### 2.1 Chat（对话配置）

**文件**: `internal/entity/chat.go` → 表 `dialog`

| 字段 | 类型 | 说明 |
|------|------|------|
| ID | string(32) | 主键 |
| TenantID | string | 所属租户 |
| Name | string | 对话名称 |
| LLMID | string | 对话模型 |
| LLMSetting | JSONMap | 模型参数（temperature, top_p 等） |
| PromptType | string | simple / system（提示词类型） |
| PromptConfig | JSONMap | 提示词配置 |
| MetaDataFilter | JSONMap | 元数据过滤条件 |
| SimilarityThreshold | float64 | 相似度阈值 |
| VectorSimilarityWeight | float64 | 向量相似度权重 |
| TopN | int64 | 检索 topN |
| RerankCandidatesCount | int64 | 重排候选数 |
| TopK | int64 | 最终返回 chunk 数 |
| DoRefer | string | 是否展示引用 |
| RerankID | string | 重排模型 |
| KBIDs | JSONSlice | 关联知识库列表 |

### 2.2 ChatSession（会话）

**文件**: `internal/entity/chat.go` → 表 `conversation`

| 字段 | 说明 |
|------|------|
| ID | 会话 ID |
| DialogID | 所属对话 |
| Name | 会话名称 |
| Message | 消息历史（JSON） |
| Reference | 引用历史（JSON） |

### 2.3 ConversationHistory（消息历史）

**文件**: `internal/entity/conversation_history.go`

存储每条消息的详细内容：role、content、references、feedback 等。

## 3. 核心服务

### 3.1 ChatPipelineService

**文件**: `internal/service/chat_pipeline.go`

RAG 问答的核心引擎，被 OpenAI 兼容接口和普通对话接口共用。

```go
type ChatPipelineService struct {
    ModelFactory *ModelFactory
    MetadataSvc  *MetadataService
    kbDAO        *dao.KnowledgebaseDAO
}

// 标准 RAG 问答（含多路检索）
func (s *ChatPipelineService) AsyncChat(ctx, req) (<-chan *AsyncChatResult, error)

// 单轮问答（无检索上下文，纯 LLM）
func (s *ChatPipelineService) AsyncChatSolo(ctx, req) (<-chan *AsyncChatResult, error)
```

### 3.2 AsyncChatResult

```go
type AsyncChatResult struct {
    Answer       string                 // 回答内容
    Reasoning    string                 // 推理内容（<think>）
    Reference    map[string]interface{} // 引用
    AudioBinary  interface{}            // 语音二进制
    Prompt       string                 // 实际 prompt
    CreatedAt    float64                // 时间戳
    Final        bool                   // 是否最后一条
    StartToThink bool                   // 开始推理标记
    EndToThink   bool                   // 结束推理标记
}
```

### 3.3 ChatSessionService

**文件**: `internal/service/chat_session.go`

管理会话生命周期与消息持久化：
- `ChatCompletions`：对话补全主入口
- `CreateSession` / `DeleteSessions` / `ListChatSessions`
- 消息反馈（点赞/踩）

### 3.4 AskService

**文件**: `internal/service/ask_service.go`

问答服务的流式入口，负责组织完整的 ask pipeline。

```go
type AskService struct {
    chunkService *chunk.ChunkService
    // ...
}

func (s *AskService) Stream(ctx, req) (<-chan *AsyncChatResult, error)
```

### 3.5 CitationService

**文件**: `internal/service/citation.go`

引用装饰服务：
```go
func InsertCitations(answer, chunks, threshold) (string, []Citation)
```

算法：句子切分 → 编码 → 余弦相似度 → 阈值匹配 → 插入 `[ID:n]` 引用标记。

## 4. RAG 问答完整流程

```
用户问题
   │
   ▼
1. 加载对话配置（LLM、知识库、检索参数）
   │
   ▼
2. 查询理解
   ├─ 关键词提取
   ├─ 元数据过滤条件解析
   └─ 同义词扩展
   │
   ▼
3. 多路检索
   ├─ SQL 检索（结构化查询）
   ├─ 向量检索（KNN）
   ├─ Web 搜索（可选）
   └─ KG 知识图谱检索（可选）
   │
   ▼
4. 重排序（Rerank 模型）
   │
   ▼
5. 上下文构建
   ├─ TOC / 子 chunk 展开
   ├─ 按 token 限制裁剪
   └─ 拼接为 Prompt 上下文
   │
   ▼
6. Prompt 构建
   ├─ System Prompt（角色设定）
   ├─ 检索上下文
   ├─ 对话历史
   └─ 用户问题
   │
   ▼
7. LLM 流式生成
   ├─ ChatModel.Stream()
   ├─ reasoning_content 与 content 分离
   └─ SSE 事件推送
   │
   ▼
8. 引用装饰
   ├─ 句子切分
   ├─ 与 chunk 余弦相似度匹配
   └─ 插入 [ID:n] 标记
   │
   ▼
9. 返回流式结果
```

## 5. 流式响应

通过 SSE（Server-Sent Events）推送，每个事件为一个 `AsyncChatResult`：

```
data: {"answer":"根据","reference":{...},"final":false}
data: {"answer":"检索结果","reference":{...},"final":false}
...
data: {"answer":"。","reference":{...},"final":true}
```

推理内容（reasoning）通过独立字段推送，前端可渲染为 `<think>` 标签。

## 6. 引用机制

1. 检索返回的每个 chunk 有唯一 ID
2. LLM 生成答案后，`InsertCitations` 将答案句子与 chunk 做语义匹配
3. 相似度超过阈值的句子插入 `[ID:n]` 引用标记
4. 前端将 `[ID:n]` 渲染为可点击的引用角标

## 7. 相关问题推荐

**文件**: `internal/service/related_question.go`

基于当前对话内容，通过 LLM 生成相关问题推荐，提升用户体验。

## 8. 思维导图

**文件**: `internal/service/mindmap.go`（handler 层）

- `POST /api/v1/chat/mindmap`
- 基于对话内容生成结构化思维导图
- 输出 JSON 格式的节点-边结构

## 9. 语音交互

### 9.1 TTS（语音合成）

**文件**: `internal/agent/audio/tts.go`

- `POST /api/v1/chat/audio/speech`
- 调用租户配置的 TTS 模型生成语音
- 返回音频二进制流

### 9.2 ASR（语音识别）

- `POST /api/v1/chat/audio/transcription`
- 调用租户配置的 ASR 模型将音频转文字

## 10. OpenAI 兼容接口

`POST /api/v1/openai/:chat_id/chat/completions`

提供 OpenAI 兼容的对话补全 API，支持：
- stream 流式输出
- tools 函数调用
- 与标准 OpenAI SDK 兼容

## 12. 关键技术点

1. **多路检索融合**：向量 + 关键词 + KG + Web 多路召回
2. **流式输出**：SSE 实时推送，支持 reasoning 分离
3. **引用装饰**：语义匹配自动标注引用来源
4. **Token 预算控制**：按 LLM context window 裁剪检索上下文
5. **模型容错**：支持模型 failover 链（`EinoChatModel`）
6. **OpenAI 兼容**：降低接入门槛，兼容生态工具
