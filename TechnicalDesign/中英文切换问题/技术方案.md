# 内置智能体模板中英文切换 — 技术方案

> 版本：v1.0  
> 日期：2026-10-22  
> 目标：在保障现有功能不受影响的前提下，将 19 份内置智能体模板的 **DSL 提示词** 从英文切换为中文。**title / description 卡片文本已有多语言 map，不在本次改动范围。**

---

## 一、现状分析

### 1.1 模板分布

模板数据以 JSON 文件形式固化在仓库内，由 `SeedCanvasTemplates`（`internal/dao/canvas_template_seed.go:39`）在服务启动时自动 upsert 到 `canvas_template` 表。

```
internal/agent/templates/
├── your_starter_dataset_chatbot.json        # 入门级知识库聊天助手
├── smart_customer_service_specialist.json   # 智能客服专员
├── web_search_assistant.json                # 网页搜索助手
├── deep_research.json                       # 深度研究员
├── seo_article_writer.json                  # SEO 文章写手
├── market_seo_article_writer.json           # 市场 SEO 文章写手
├── stock_market_research_assistant.json     # 股票研究助手
├── trip_planner.json                        # 旅行规划师
├── text2sql_data_expert.json                # Text2SQL 数据专家
├── data_analysis_beginner_assistant.json    # 数据分析初级助手
├── photo_text_translator.json               # 图文翻译
├── customer_feedback_dispatcher.json        # 客户反馈分发器
├── user_interaction.json                    # 用户交互
├── cajal_scientific_paper_agent.json        # Cajal 论文助手
├── reflective_academic_paper_generator.json # 反思式学术论文生成器

└── advanced_ingestion_pipeline.json         # 高级摄取管线（非 agent，是 ingestion pipeline 模板）
```

### 1.2 已有多语言支持的范围（✅ 无需改动）

**Title / Description 卡片文本** —— 已经是 `JSONMap`（即 `map[string]any`）结构，种子文件里已维护 `{en, de, zh}` 三种语言：

```json
// your_starter_dataset_chatbot.json
{
  "title":        { "en": "Your starter dataset chatbot",        "zh": "入门级知识库聊天助手" },
  "description":  { "en": "This is a document Q&A system...",     "zh": "基于知识库的入门级助手..." }
}
```

后端 entity（`CanvasTemplate`）和前端 interface（`IFlowTemplate`）都按语言 map 定义，前端 `template-card.tsx` 里按 `i18n.language === 'zh' ? 'zh' : 'en'` 取值渲染。**这条链路完全通了，不需要任何代码改动。**

### 1.3 需要翻译的内容（⚠️ 全是英文硬编码）

模板 JSON 里 **DSL（`dsl` 字段）内部** 的提示词文本，全是英文纯字符串。覆盖 **约 497 处**，分布在 19 份模板中。

### 1.4 关键结构：双路径同步

ReactFlow 画布设计导致每个提示词在 DSL 里出现 **两份**，**翻译时必须同步更新**，否则画布打开后节点表单显示英文、运行时却用中文（或反过来）。

以 `your_starter_dataset_chatbot.json` 为例：

| 路径 | 用途 | 说明 |
|---|---|---|
| `dsl.components.{nodeId}.obj.params.sys_prompt` | 后端运行时读取 | **运行时真正执行的提示词** |
| `dsl.graph.nodes[].data.form.sys_prompt` | 前端画布节点表单 | 用户编辑时看到的 UI 文本 |
| `dsl.components.{nodeId}.obj.params.prompts[].content` | 运行时 | Agent 节点的消息模板 |
| `dsl.graph.nodes[].data.form.prompts[].content` | 前端画布 | 同上的节点表单副本 |
| `dsl.components.{nodeId}.obj.params.description` | 运行时 | 工具/节点描述 |
| `dsl.graph.nodes[].data.form.description` | 前端画布 | 同上 |
| `dsl.components.{nodeId}.obj.params.user_prompt` | 运行时 | Tool 节点的工具使用指令 |
| `dsl.graph.nodes[].data.form.user_prompt` | 前端画布 | 同上 |
| `dsl.graph.nodes[].data.form.text` | 前端画布 | **仅 Note 节点** 的说明文字（没有 components 侧的副本） |

**总结规则：**
- `sys_prompt` / `prompts[].content` / `user_prompt` / `description` → **两处**（components + graph.nodes.form）
- Note 节点的 `text` → **只有 graph.nodes.form 一处**
- Node 名称（`label` / `name` / 节点 ID）→ **不改**，保持英文（这些是机器可读标识）

## 二、方案对比

### 方案 A：纯数据层替换（推荐）

**做法**：把 19 份 JSON 模板里 `dsl` 字段下所有英文提示词直接改成中文文本，保持 DSL 其他结构（节点 ID、边、JSON key）完全不动。

**运行机制**：`SeedCanvasTemplates` 在服务启动时执行 `ON CONFLICT(id) DO UPDATE SET dsl = excluded.dsl`，自动把更新后的 DSL 刷入 `canvas_template` 表。**已有智能体不受影响**——它们的 DSL 在创建时就是模板的独立副本，存在 `user_canvas` / `user_canvas_version` 表中，与模板解耦。

| 维度 | 评估 |
|---|---|
| 代码改动量 | **0 行** —— 只改 JSON 文件 |
| 运行时风险 | **零** —— 不改变后端 component 读取 prompt 的逻辑，不改变前端画布解析 DSL 的逻辑 |
| 维护成本 | 低 —— 后续新增模板直接写中文即可 |
| 历史兼容 | 完美 —— 已有 agent 的 DSL 独立副本不受种子刷新影响 |
| 多语言扩展性 | 一般 —— 要切英文只能靠英文模板文件（或额外加一份 `*_en.json`） |

### 方案 B：DSL 内部做多语言 map（类似 title/description）

**做法**：把每个 prompt 从 `"sys_prompt": "English text"` 改成 `"sys_prompt": {"en": "...", "zh": "..."}`，然后在后端 component 运行时和前端画布渲染时按当前语言取值。

| 维度 | 评估 |
|---|---|
| 代码改动量 | 大 —— 所有读 prompt 的 component（Agent/LLM/Tool 等）都要加一层 map→string 解析；前端画布节点表单要加语言选择逻辑 |
| 运行时风险 | 高 —— 每读一个 prompt 都要判断类型（string 还是 map），类型错了就 panic；DSL 校验逻辑也要改 |
| 维护成本 | 高 —— 每个新模板都要维护两份文本；seed 逻辑要处理新结构 |
| 历史兼容 | 差 —— 已有 agent 的 DSL 是纯 string，运行时必须做类型兼容（string → map 回退） |

**结论：不推荐。** 收益（运行时可切语言）不足以覆盖风险和复杂度。

### 方案 C：模板 JSON 增加 `dsl_zh` 字段

**做法**：模板 JSON 里保留现有英文 `dsl`，新增 `"dsl_zh": {...}` 存中文版本。前端 `CreateAgentDialog` 按当前语言挑 `dsl` 或 `dsl_zh`。

| 维度 | 评估 |
|---|---|
| 代码改动量 | 小 —— 后端 entity 加 `DSLZHFallback JSONMap`，seed upsert 加一列，前端 create-agent-dialog 改一下 |
| 运行时风险 | 低 —— 不改 component，只是前端选哪份 DSL 的问题 |
| 维护成本 | 中 —— 模板文件两份 DSL，新增模板要同时写 |
| 历史兼容 | 好 —— 同方案 A |

**缺点**：模板文件体积翻倍；后端 entity 要加新列；后续每次 seed 更新两份 DSL。

### 方案 D：运行时 LLM 实时翻译

**做法**：模板里仍保留英文，运行时根据用户语言用 LLM 翻译 prompt。

**否决原因**：每次运行都调 LLM = 钱 + 延迟 + 不稳定（同一句 prompt 每次翻译可能不一样，影响 agent 行为确定性）。

## 三、推荐方案：方案 A（纯数据层替换）

### 3.1 执行步骤

```
┌─────────────────────────────────────────────────────────────┐
│ Step 1: 翻译 19 份 JSON 模板文件（本方案核心工作）          │
│   - 仅翻译 dsl 字段下的提示词文本                           │
│   - 保持 DSL 结构、节点 ID、边、params key 完全不变         │
│   - 严格遵循「双路径同步」规则                              │
│   - title/description 保持现有多语言 map 不动              │
└─────────────────────────────────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│ Step 2: 重启后端服务                                        │
│   - SeedCanvasTemplates 自动 upsert dsl 列                 │
│   - canvas_template 表中 DSL 被刷成中文版本                │
│   - 耗时：< 1 秒（只是 JSON 字段覆盖）                      │
└─────────────────────────────────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│ Step 3: 验证                                                │
│   - 新建智能体 → 画布节点表单显示中文提示词                 │
│   - 试运行 → 运行时使用中文提示词（不影响功能）              │
│   - 已有智能体 → 提示词保持原样（英文），不受影响           │
│   - 重启后再次验证 → 种子刷新不会覆盖已创建的智能体         │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 翻译规则

| 类别 | 字段 | 值类型 | 翻译方向 | 注意事项 |
|---|---|---|---|---|
| Agent / LLM 系统提示词 | `sys_prompt` | 长 Markdown | EN → ZH | 保留 `{sys.query}` `{context}` 等变量占位符原样；保留 `# Role` / `# Principles` 等 Markdown 结构 |
| 消息模板 | `prompts[].content` | 短字符串 | EN → ZH | 保留 `{...}` 变量占位符 |
| 节点/工具描述 | `description` | 短字符串 | EN → ZH | 用于节点表单 UI 提示 |
| 工具使用指令 | `user_prompt` | 短字符串 | EN → ZH | Tool 节点专属，告诉 Agent 什么时候调用这个工具 |
| Note 节点说明 | `text` | 长 Markdown | EN → ZH | **只有 graph.nodes.form 一处，components 侧没有** |
| Node 显示名 | `label` / `name` | 字符串 | **不改** | ReactFlow 内部标识，保持英文 |
| Node ID | `Agent:StalePandasDream` | 字符串 | **不改** | 机器生成，保持英文 |
| 枚举值 / 布尔 / 数字 | `max_rounds: 5` | 原始类型 | **不改** | 控制参数，不是用户可见文本 |

### 3.3 双路径同步清单

下面的表格列出每个提示词字段需要同时更新的两个路径，翻译时按此对照。

| 字段 | components 路径 | graph.nodes 路径 | 涉及节点类型 |
|---|---|---|---|
| `sys_prompt` | `components.*.obj.params.sys_prompt` | `graph.nodes[].data.form.sys_prompt` | Agent, LLM |
| `prompts[].content` | `components.*.obj.params.prompts[].content` | `graph.nodes[].data.form.prompts[].content` | Agent, LLM |
| `description` | `components.*.obj.params.description` | `graph.nodes[].data.form.description` | Tool, Retrieval, 其他工具节点 |
| `user_prompt` | `components.*.obj.params.user_prompt` | `graph.nodes[].data.form.user_prompt` | Tool |
| Note 说明 | _(不存在)_ | `graph.nodes[].data.form.text` | Note（只有前端路径） |

## 五、风险与限制

### 5.1 已有智能体不会自动变中文

模板种子只在 `canvas_template` 表刷新 DSL。**已创建的智能体**（`user_canvas` / `user_canvas_version` 表）持有模板的独立副本，不会被种子刷新覆盖。

- **预期行为**：老智能体提示词保持英文不变，新建的从模板创建的智能体提示词是中文
- **如果需要批量迁移老智能体**：单独开一个脚本/后台任务，把 `user_canvas.dsl` 里的 sys_prompt / prompts 等字段批量替换为对应中文。**不在本次改动范围。**

### 5.2 JSON 文件体积 & base64 头像

每个模板 JSON 末尾包含一段 data URI base64 头像图片，行数占比不小（`your_starter_dataset_chatbot.json` 里 avatar 字段从约第 344 行到末尾）。翻译时 **不要动 avatar 字段**，避免二进制数据损坏。

### 5.3 `advanced_ingestion_pipeline.json` 不是 agent 模板

它属于 ingestion pipeline 模板（种子加载时也会被 `SeedCanvasTemplates` 覆盖），提示词量少（13 处），翻译时一并处理即可。

### 5.4 翻译质量 & 术语一致性

- 变量占位符（`{sys.query}` `{context}` `{Agent@content}` 等）**原样保留**，不要翻译成中文花括号
- Markdown 结构（`# Role` `## 当信息不可用时`）保留层级，正文翻成中文
- 术语一致性：
  - Retrieval → 检索
  - Knowledge Base → 知识库
  - User Query → 用户查询
  - Workflow / Chatflow → 工作流 / 对话流（保持与产品 UI 一致）
  - 其他 Dify 风格术语参考 Dify 中文版

### 5.5 回滚方式

如果中文提示词效果不好想回退：

```bash
git revert <translation-commit>    # 恢复 JSON 到英文版本
# 重启服务 → SeedCanvasTemplates 自动刷回英文 DSL
```

**零代码改动的回滚成本。**

## 六、验收标准

| # | 验证点 | 通过条件 |

## 八、与现有多语言支持的关系

```
当前已支持多语言的部分:
├── template.title           ✅ JSONMap {en, de, zh}  ← 保持不动
├── template.description     ✅ JSONMap {en, de, zh}  ← 保持不动
├── i18n locale 翻译         ✅ react-i18next         ← 保持不动
└── UI 组件文本              ✅ react-i18next         ← 保持不动

本次新增中文的部分:
└── template.dsl.* 提示词    ⚠️ 硬编码英文 → 纯数据层替换为中文文本
    └── CanvasState / component 读取逻辑  ← 完全不动（它们读 string，不管是英文还是中文）
```
