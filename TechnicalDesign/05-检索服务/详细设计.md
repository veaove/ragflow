# 检索服务 - 详细设计

## 1. 模块概述

检索服务是 RAGFlow 的核心查询引擎，提供混合检索（向量 + 关键词）、重排序、元数据过滤、同义词扩展、知识图谱检索等能力，为对话问答和知识库检索提供底层支撑。

## 3. 混合检索算法

### 3.1 检索流程

```
用户查询
   │
   ▼
查询理解
   ├─ 同义词扩展（SynonymService）
   ├─ 关键词提取（QueryBuilder）
   └─ 元数据过滤条件解析
   │
   ▼
多路召回
   ├─ 向量检索（KNN）
   ├─ 关键词检索（BM25 / 全文）
   └─ 知识图谱检索（可选）
   │
   ▼
融合排序
   └─ vector_similarity_weight 加权融合
   │
   ▼
重排序（可选）
   └─ RerankModel.Rerank(docs, query)
   │
   ▼
元数据过滤
   │
   ▼
返回结果
```

### 3.2 向量检索

通过 `EmbeddingModel` 将查询文本编码为向量，调用 Doc Engine 的 KNN 搜索：

```go
// 构造 SearchRequest
searchReq := &types.SearchRequest{
    DatasetIDs: kbIDs,
    QueryVector: queryVector,
    KNNTopK:     knnTopK,
    // ...
}
result, _ := docEngine.Search(ctx, searchReq)
```

### 3.3 关键词检索

基于分词器的全文检索（BM25），由 Doc Engine 的全文索引能力提供。

### 3.4 融合排序

```go
finalScore = vector_similarity_weight * vectorScore
           + (1 - vector_similarity_weight) * keywordScore
```

`vector_similarity_weight` 由知识库或对话配置决定，默认 0.3-0.7。

## 4. 重排序（Rerank）

**文件**: `internal/service/nlp/reranker.go`

### 4.1 Rerank 策略

```go
func Rerank(ctx, req, result, rerankModel, engineType) error
```

三种策略：
1. **Model Rerank**：调用租户的 Rerank 模型对候选 chunk 精排
2. **Infinity Fallback**：Infinity 引擎内置 rerank 能力
3. **Standard Rerank**：基于 TokenSimilarity 的本地重排

### 4.2 Model Rerank 流程

```go
// 1. 提取候选文档的 content / title / keywords
// 2. 构造 docs 列表
docs := []string{chunk["content_with_weight"]}
// 3. 调用 rerank 模型
scores, _ := rerankModel.Rerank(ctx, question, docs)
// 4. 按分数重排
```

## 5. 同义词扩展

**文件**: `internal/service/nlp/synonym.go`

- 加载知识库级别的同义词组 + 内置词库（`rag/res/synonym.json`）
- 查询时对关键词进行同义词替换/扩展
- 通过 `QueryBuilder` 实现，支持中英文

## 6. 元数据过滤

**文件**: `internal/service/metadata_filter.go`

- 支持按文档元数据字段过滤（如 `author = "张三"`、`date > "2024-01-01"`）
- 优先下推到 Doc Engine（`FilterDocIdsByMetaPushdown`）
- 不支持下推时在内存中过滤

## 7. 知识图谱检索

**文件**: `internal/service/graph/`

| 文件 | 职责 |
|------|------|
| `search.go` | 图谱搜索入口 |
| `retrieval.go` | 基于图谱的检索 |
| `scoring.go` | 图谱节点打分 |
| `pipeline.go` | 图谱遍历管线 |
| `types.go` | 图谱数据结构 |

图谱检索用于增强问答的深度推理能力，通过实体-关系遍历找到相关知识。

## 8. 知识库导航

**文件**: `internal/service/nav/`, `internal/service/nlp/datasetnav.go`

- 基于向量聚类的导航树生成
- `NavService` 提供 `Search` / `UpsertDoc` 接口
- 支持导航节点的 LLM 摘要合并（`NavMergeLLM`）

## 9. Wiki 搜索

**文件**: `internal/service/wikisearch/`

- 对知识编译产出的 Wiki 页面进行搜索
- 过滤条件：`compile_kwd = "wiki_page"`
- 支持普通 chunk 与 wiki page 的混合召回

## 10. 关键技术点

1. **多策略融合**：向量 + 关键词 + 图谱三路召回，加权融合
2. **可配置权重**：`vector_similarity_weight` 灵活控制向量/关键词比例
3. **模型化重排**：支持接入第三方 Rerank 模型提升精度
4. **同义词增强**：查询扩展提升召回率
5. **元数据下推**：优先利用引擎能力过滤，减少内存开销
6. **图谱增强**：知识图谱提供深度推理能力
