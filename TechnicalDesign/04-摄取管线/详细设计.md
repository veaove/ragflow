# 摄取管线 - 详细设计

## 1. 模块概述

摄取管线（Ingestion Pipeline）是 RagFlow 知识加工的核心链路，负责将原始文档转化为可检索的 chunk 并写入向量引擎。由独立的 **Ingestor** 服务进程承载，通过 NATS 消息队列与 API 服务解耦。

## 2. 整体架构

```
API Server                    Ingestor Process
┌──────────┐    NATS     ┌──────────────────────────┐
│ 上传文档  │ ─────────→ │  IngestionService         │
└──────────┘             │  ┌────────────────────┐  │
                         │  │ dispatchLoop       │  │
                         │  └────────┬───────────┘  │
                         │           │              │
                         │  ┌────────▼───────────┐  │
                         │  │ Worker Pool        │  │
                         │  │  ┌──────────────┐  │  │
                         │  │  │PipelineExecutor│  │  │
                         │  │  └──────┬───────┘  │  │
                         │  └─────────┼──────────┘  │
                         │            │             │
                         │  ┌─────────▼──────────┐  │
                         │  │ Doc Engine (索引)   │  │
                         │  └────────────────────┘  │
                         └──────────────────────────┘
```

## 3. 核心服务

### 3.1 Ingestor（摄取主控）

**文件**: `internal/ingestion/service/ingestion_service.go`

```go
type Ingestor struct {
    id, name string
    ctx, cancel context.Context

    // 配置
    maxConcurrency          int32
    supportedDocTypes       []string
    heartbeatInterval       time.Duration  // 默认 2s
    memoryReconcileInterval time.Duration

    // 运行时状态
    currentTasks   map[string]struct{}  // 正在处理的 task ID
    activeWorkers  atomic.Int32
    activeLeases   map[*Heartbeat]*activeLease
}
```

**核心方法**：
- `Start(ctx)`：初始化 NATS consumer、调度待处理任务、启动 worker pool
- `dispatchLoop()`：从 NATS PullMessage → 投递到 worker inbox
- `workerLoop()`：消费 worker inbox → 执行 PipelineExecutor
- `Heartbeat`：续约消息 ACK 截止时间（必须 < NATS ack deadline 5s）

### 3.2 Pipeline（管线）

**文件**: `internal/ingestion/pipeline/pipeline.go`

```go
type Pipeline struct {
    taskID     string

    canvas     *canvas.Canvas  // DSL 编译后的画布
    tracker    *ProgressTracker

}

// 从 DSL 构造管线
func NewPipelineFromDSL(dsl map[string]any, opts ...PipelineOption) (*Pipeline, error)

// 执行管线
func (p *Pipeline) Run(ctx) (*PipelineResult, error)
```

**ProgressSink 接口**：
```go
type ProgressSink interface {
    OnComponentTotal(total int)
    OnComponentProgress(current int)
}
```

### 3.3 PipelineExecutor（任务执行器）

**文件**: `internal/ingestion/task/pipeline_executor.go`

```go
type PipelineExecutor struct {
    docEngine engine.DocEngine
    // ...
}

func (e *PipelineExecutor) Execute(ctx, task *IngestionTask) (*PipelineResult, error)
```

**执行流程**：
1. 加载 Pipeline DSL（按 parser_id 选择内置模板）
2. 编译 Canvas → Eino Workflow
3. 执行 Workflow（Parser → Chunker → ...）
4. 后处理：chunk 规范化、parent-child 关系、table metadata
5. 嵌入向量（Embedder）
6. 写入索引（ChunkIndexWriter）
7. 知识编译（tree/wiki/mindmap/structure）
8. 持久化结果到 Document

## 4. 管线阶段组件

### 4.1 Parser（解析器）

**文件**: `internal/ingestion/component/parser.go`

- 输入：文档二进制流
- 输出：`[]DocItem`（文档元素列表）
- 根据文件后缀分发到具体解析器（`parser/parser/`）
- 支持视觉增强（vision_enhancement）

### 4.2 Chunker（分块器）

**文件**: `internal/ingestion/component/chunker/`

| 分块器 | 文件 | 算法 |
|--------|------|------|
| Token | `token.go` | 按 token 数智能分块，支持 overlap、子分隔符、JSON 处理 |
| Delimiter | `delim.go` | 按自定义分隔符切分 |
| Title | `title.go` | 按标题层级（#/##/###）分块 |
| Table | `table.go` | 表格分块，保持表格上下文 |
| QA | `qa.go` | 问答对分块（Q:\nA:） |
| Page | `page.go` | 按页分块（PDF） |
| One | `one.go` | 整体作为一个 chunk |

**TokenChunker 核心逻辑**（`token.go`）：
1. 按 delimiter 切分为 units
2. 用 tokenizer 计算每个 unit 的 token 数
3. 合并 units 直到达到 token_size 限制
4. 支持 overlap（相邻 chunk 重叠部分 token）
5. 超预算 unit 保留不丢弃
6. JSON chunk 按 children delim 处理

### 4.3 Embedder（嵌入器）

**文件**: `internal/ingestion/task/embedder.go`

```go
type embedder struct {
    model          *models.EmbeddingModel
    tokenLimiter   *tokenizer.Limiter
    maxTokens      int
    batchSize      int
}

func (e *embedder) Encode(ctx, chunks []Chunk) error
```

- 批量调用租户配置的 Embedding 模型
- 支持 token 限流（避免超限）
- 支持重试与超时

### 4.4 ChunkIndexWriter（索引写入器）

**文件**: `internal/ingestion/task/chunk_index_writer.go`

- 将 chunk（含向量、文本、元数据）写入 Doc Engine
- 支持批量写入
- 支持 parent-child chunk 结构

### 4.5 KnowledgeCompiler（知识编译器）

**文件**: `internal/ingestion/component/knowledge_compiler/`

对已索引 chunk 进行高阶加工：

| 编译类型 | 目录 | 产出 | 算法 |
|---------|------|------|------|
| Tree | `tree/` | 层次知识树 | RAPTOR 摘要 + 分水岭聚类 |
| Wiki | `wiki/` | Wiki 页面 | 主题规划 → 摘要 → 增量更新 |
| Mindmap | `mindmap/` | 思维导图 | LLM 生成结构 |
| Structure | `structure/` | 知识图谱 | 实体抽取 + 关系链 + 证据合并 |

调度由 `internal/ingestion/knowledge_compile/service.go` 管理，通过 NATS 消息驱动。

## 7. 心跳与租约机制

Ingestor 通过心跳保持 NATS 消息的 ACK 截止时间续约：

```
Worker 开始处理消息
    │
    ├── 启动 Heartbeat goroutine（每 2s）
    │       │
    │       └── 调用 msg.InProgress() 续约
    │
    ├── 执行业务逻辑
    │
    └── 完成 → msg.Ack() 或 msg.Nak()
```

- 心跳间隔 2s < NATS ack deadline 5s
- 防止 broker 在处理过程中重新投递消息

## 8. 关键技术点

1. **DSL 驱动**：管线以 JSON DSL 描述，支持自定义编排
2. **NATS 异步**：摄取任务通过消息队列分发，API 与 Ingestor 解耦
3. **Worker Pool**：可配置并发数，充分利用 CPU
4. **心跳续约**：长任务通过 InProgress 保持消息不被重投
5. **幂等处理**：content_hash 去重，避免重复解析
6. **进度追踪**：ProgressTracker 实时上报解析进度
7. **知识编译**：tree/wiki/mindmap/structure 提升知识密度
