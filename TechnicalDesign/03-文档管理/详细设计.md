# 文档管理 - 详细设计

## 1. 模块概述

文档管理模块负责文件上传、文档解析触发、文档状态追踪、文件版本管理（类 Git commit）与文件夹组织。

## 2. 核心数据模型

### 2.1 Document（文档）

**文件**: `internal/entity/document.go` → 表 `document`

| 字段 | 类型 | 说明 |
|------|------|------|
| ID | string(32) | 主键 |
| KbID | string | 所属知识库 |
| ParserID | string(32) | 解析器类型 |
| PipelineID | string(32) | 摄取管线 ID |

| SourceType | string | 来源：local / connector / ... |
| Type | string | 文档类型 |

| Size | int64 | 文件大小 |
| TokenNum | int64 | Token 数 |
| ChunkNum | int64 | Chunk 数 |

| ProcessDuration | float64 | 处理耗时（秒） |

| Status | string(1) | 状态 |

### 2.2 File（文件）

**文件**: `internal/entity/file.go`

文件系统实体，支持文件夹层级：
- 文件名、路径、大小、类型
- 所属文件夹（parent_id）
- 关联的知识库（通过 link-to-datasets）

### 2.3 FileCommit（文件提交）

**文件**: `internal/entity/file_commit.go`

类 Git 的版本控制：
- CommitID、Message、Author
- 所属文件夹 / 工作区
- 变更文件列表（增删改）
- 提交时间

## 4. 文档处理状态机

```
          ┌─────────┐
          │  待处理  │ (TaskStatusUnstart = "0")
          └────┬────┘
               │ 触发摄取
          ┌────▼────┐
   ┌──────│  运行中  │ (TaskStatusRunning = "1")
   │      └────┬────┘
   │           │
   │     ┌─────┼─────┐
   │     │     │     │
   │  ┌──▼──┐ ┌▼──┐ ┌▼────┐
   │  │完成 │ │失败│ │取消 │
   │  └─────┘ └───┘ └─────┘
   │   "3"    "4"   "2"
   │           │
   └───────────┘ 重试
```

状态字段：`TaskStatus` 枚举（`entity/dataset.go`）：
- `0` 未开始
- `1` 运行中
- `2` 已取消
- `3` 已完成
- `4` 失败
- `5` 调度中

## 5. 文档上传流程

```
POST /api/v1/datasets/:id/documents
  → 接收文件（multipart/form-data）
  → 存储到 Storage Engine（MinIO/S3）
  → 计算 content_hash
  → 创建 Document 记录（status=0）
  → 发布 NATS 消息到 ingestion_tasks
  → 返回 Document 信息
```

## 6. 文件版本控制（FileCommit）

类 Git 的版本管理模型：

```
工作区(未提交) ──commit──→ Commit 历史
     │                       │
     │  diff                 │  checkout
     └───────────────────────┘
```

- 每次 commit 记录变更文件快照
- 支持任意两个 commit 间的 diff
- 支持查看历史版本文件内容
- 支持工作区未提交变更查看

## 8. 关键技术点

1. **幂等去重**：`content_hash` 字段用于检测重复上传，避免重复解析
2. **进度追踪**：`progress` + `progress_msg` 实时反馈解析进度
3. **异步处理**：文档解析通过 NATS 异步分发，API 立即返回
4. **存储抽象**：Storage Engine 屏蔽 MinIO/S3/OSS/GCS 差异
5. **版本快照**：FileCommit 保存文件内容快照，支持历史回溯
