# 用户与租户管理 - 详细设计

## 1. 模块概述

用户与租户管理模块负责 RagFlow 的身份认证、多租户组织管理、权限控制与 API 凭证管理。是所有业务的入口与基础。

## 2. 核心数据模型

### 2.1 User（用户）

**文件**: `internal/entity/user.go` → 表 `user`

| 字段 | 类型 | 说明 |
|------|------|------|
| ID | string(32) | 主键，用户 ID |
| AccessToken | string | 访问令牌（登录态凭证） |
| Email | string | 邮箱（登录账号） |

| Name | string | 昵称 |

| Status | string(1) | 状态：1=有效，0=无效 |
| IsSuperuser | bool | 是否超级管理员 |

**文件**: `internal/entity/user_tenant.go` → 表 `user_tenant`

| 字段 | 类型 | 说明 |

### 2.4 APIToken（API 凭证）

**文件**: `internal/entity/api_token.go` → 表 `api_token`

支持三种 token 类型：
- 用户 Session Token（JWT）
- Beta API Token（用于 chatbot/agentbot 公开接口）
- App API Key（用于 Workflow/Chatflow 公开运行）

## 4. 认证流程

### 4.1 注册流程

```
POST /api/v1/users
  → 校验邮箱格式
  → 邮箱查重
  → 解密密码（前端加密传输）
  → 哈希密码存储
  → 生成 AccessToken
  → 事务创建: User + Tenant + UserTenant(role=admin) + 根文件夹
  → 返回 signed token + 用户信息
```

### 4.2 登录流程

```
POST /api/v1/users/login (或 /auth/login)
  → 按邮箱查 User
  → 解密密码
  → bcrypt 校验密码
  → 校验用户状态
  → 生成新 AccessToken 并更新
  → 更新登录时间
  → 设置 Cookie + 返回用户 profile
```

### 4.3 认证中间件

**文件**: `internal/handler/auth.go`

`AuthMiddleware` 按优先级解析凭证：
1. JWT Bearer Token（用户 Session）
2. API Token（`Authorization: Bearer <token>`）
3. Beta API Token（公开 bot 接口）

解析后将 `user`、`tenant`、`auth_via_api_token` 写入 gin context。

## 5. 权限控制

**文件**: `internal/permission/`

### 5.1 权限模型

```
Subject(UserID, TenantID)
    ↓ 对
Resource(Kind, ID)
    ↓ 执行
Action(read / write / enable)
```

### 5.2 资源类型

`ResourceKind` 枚举：Dataset、Canvas、AgentSession、Memory、File、Folder、SearchApp、Chat、ChatSession、ChatChannel、Connector、SyncTask、ModelProvider、ModelInstance、Model、MCPServer、SkillSpace

### 5.3 策略实现

- **Community 版** (`policy_ce.go`)：基于租户成员关系校验
- **Enterprise 版** (`policy_ee.go`)：RBAC 角色权限矩阵

### 5.4 数据隔离

所有业务表含 `tenant_id`，DAO 查询通过 GORM Scope 自动注入租户过滤条件（`permission/query_scope.go`），确保跨租户数据不可见。

## 7. 关键技术点

1. **密码安全**：前端 RSA 加密传输 → 后端解密 → bcrypt 哈希存储
2. **Token 机制**：AccessToken 持久化到 DB，支持主动失效
3. **事务一致性**：注册流程用 DB 事务保证 User/Tenant/UserTenant/Folder 原子创建
4. **多租户隔离**：tenant_id 列 + GORM Scope 双重保障
5. **Edition 策略**：通过构建标签区分 CE/EE 权限实现
