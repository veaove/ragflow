# 质量检查 - 详细设计

## 1. 模块概述

质量检查（QC）模块为 RAGFlow 提供知识库内容质检能力，支持定义质检规则、实时检测对话回答中的违规内容、命中高亮展示。

## 2. 核心数据模型

### 2.1 QCRule（质检规则）

**文件**: `internal/entity/qc_rule.go`

| 字段 | 说明 |
|------|------|
| ID | 规则 ID |
| TenantID | 所属租户 |
| KbID | 关联知识库（可选） |
| Name | 规则名称 |
| Keywords | 关键词列表 |
| Regex | 正则表达式 |
| Severity | 严重级别 |
| Action | 触发动作（warn/block） |
| Status | 状态 |

### 2.2 QCHit（质检命中）

**文件**: `internal/entity/qc_hit.go`

| 字段 | 说明 |
|------|------|
| ID | 命中 ID |
| RuleID | 触发的规则 |
| SessionID | 对话会话 |
| MessageID | 触发的消息 |
| Content | 命中的内容片段 |
| Highlight | 高亮位置 |
| CreateTime | 命中时间 |

## 3. 核心服务

### 3.1 QCService

**文件**: `internal/service/qc_service.go`

```go
type QCService struct {
    ruleDAO *dao.QCRuleDAO
    hitDAO  *dao.QCHitDAO
}

// 规则管理
func (s *QCService) CreateRule(ctx, req) (*QCRule, error)
func (s *QCService) ListRules(tenantID) ([]QCRule, error)
func (s *QCService) UpdateRule(id, req) error
func (s *QCService) DeleteRule(id) error

// 质检执行
func (s *QCService) CheckContent(ctx, content, sessionID) ([]QCHit, error)
```

### 3.2 QCMatcher

**文件**: `internal/service/qc_matcher.go`

质检匹配核心算法：

```go
type QCMatcher struct {
    rules []QCRule
}

func (m *QCMatcher) Match(content string) []QCMatchResult
```

**匹配逻辑**：
1. 遍历所有启用的质检规则
2. 关键词匹配：检查 content 是否包含规则关键词
3. 正则匹配：用规则 regex 匹配 content
4. 返回所有命中结果（含位置、严重级别）

### 3.3 QCHighlight

**文件**: `internal/service/qc_highlight.go`

将命中片段在回答中高亮标注：

```go
func Highlight(content string, hits []QCMatchResult) string
// 返回带高亮标记的内容
```

### 3.4 QCSanitize

**文件**: `internal/service/qc_sanitize.go`

对命中内容进行清洗（替换/脱敏）。

## 4. 实时质检流

### 4.1 WebSocket 实时推送

**端点**: `GET /api/v1/qc/stream`

- 注册在认证中间件之外（WebSocket 无法携带 Authorization header）
- 通过 `token` query 参数解析用户
- 实时推送质检命中事件

### 4.2 实时流程

```
LLM 生成回答（流式）
    │
    ▼
QCMatcher.Match(增量内容)
    │
    ├─ 命中 → 记录 QCHit → WebSocket 推送
    └─ 未命中 → 继续
    │
    ▼
回答生成完成 → 返回完整命中列表
```

## 5. HTTP 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/v1/qc/rules | 规则列表 |
| POST | /api/v1/qc/rules | 创建规则 |
| PUT | /api/v1/qc/rules/:id | 更新规则 |
| DELETE | /api/v1/qc/rules/:id | 删除规则 |
| GET | /api/v1/qc/hits | 命中记录 |
| GET | /api/v1/qc/stream | 实时质检 WebSocket |

## 6. 关键技术点

1. **双模式匹配**：关键词 + 正则，灵活定义规则
2. **实时检测**：流式回答过程中增量匹配，WebSocket 推送
3. **高亮展示**：命中片段在前端高亮标注
4. **动作分级**：warn（警告）/ block（拦截）
5. **审计留痕**：所有命中记录持久化到 QCHit 表
