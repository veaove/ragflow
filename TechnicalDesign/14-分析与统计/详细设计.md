# 分析与统计 - 详细设计

## 1. 模块概述

分析与统计模块提供 RAGFlow 的运营数据分析能力，包括咨询日志、问答统计、系统监控与 Langfuse 可观测性集成。

## 2. 核心数据模型

### 2.1 Analytics（咨询日志）

**文件**: `internal/entity/analytics.go`

| 字段 | 说明 |
|------|------|
| ID | 日志 ID |
| TenantID | 所属租户 |
| UserID | 操作用户 |
| DialogID | 对话 ID |
| SessionID | 会话 ID |
| Question | 用户问题 |
| Answer | 回答内容 |
| References | 引用 |
| Latency | 响应耗时（ms） |
| Tokens | Token 消耗 |
| Feedback | 用户反馈 |
| CreateTime | 时间 |

### 2.2 Stats（系统统计）

系统级聚合统计，通过查询实时计算。

## 3. 核心服务

### 3.1 AnalyticsService

**文件**: `internal/service/analytics_service.go`

```go
type AnalyticsService struct {
    analyticsDAO *dao.AnalyticsDAO
}

// 日志记录
func (s *AnalyticsService) LogChat(ctx, log *Analytics) error

// 查询
func (s *AnalyticsService) ListAnalytics(tenantID, filter) ([]Analytics, int64, error)
func (s *AnalyticsService) GetAnalyticsSummary(tenantID, timeRange) (*Summary, error)
```

**统计维度**：
- 问答量趋势（按日/周/月）
- 平均响应耗时
- Token 消耗统计
- 引用命中率
- 用户反馈分布
- 热门问题排行

### 3.2 StatsService

**文件**: `internal/service/stats.go`

```go
type StatsService struct{}

func (s *StatsService) GetStats() (*SystemStats, error)
```

返回系统整体统计：
- 知识库数量
- 文档数量
- Chunk 数量
- 用户数量
- 对话数量

### 3.3 LangfuseService

**文件**: `internal/service/langfuse.go`

集成 Langfuse 实现 LLM 调用可观测性：

```go
type LangfuseService struct{}

func (s *LangfuseService) SetAPIKey(tenantID, host, publicKey, secretKey) error
func (s *LangfuseService) GetAPIKey(tenantID) (*LangfuseInfo, error)
func (s *LangfuseService) DeleteAPIKey(tenantID) error
```

- 记录每次 LLM 调用的输入、输出、耗时、Token
- 支持按租户配置 Langfuse 凭证
- 追踪 Agent 执行链路

## 4. 运行记录与审计

### 4.1 RunService

**文件**: `internal/handler/run.go`

记录 Agent / Workflow / Chatflow 的运行历史：
- `GET /api/v1/runs`：运行列表
- `GET /api/v1/runs/:id`：运行详情
- `GET /api/v1/runs/:id/nodes`：节点执行日志

### 4.2 AuditService

```
GET /api/v1/audits
```

审计日志，记录关键操作。

## 7. 关键技术点

1. **全链路追踪**：Analytics + Langfuse 双层观测
2. **多维统计**：支持按时间、知识库、用户等维度聚合
3. **运行审计**：Agent 运行节点级日志
4. **资源管控**：CPU/内存/并发可在线配置
5. **健康检查**：多层级健康探针
